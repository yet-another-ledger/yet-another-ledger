# M20 · 固定资产台账、AI 残值估计与 AI API 协议切换

> 🌐 [English](M20.md) · **中文**

> 作者于 2026-11-23 确认本设计。[路线图](../roadmap_zh.md#进度追踪)记录实施和验收进度。

## 目标与范围

为福禄克测试仪、家用储能电池等设备维护年度固定资产台账。支持从已登记的采购转入，也可在确认新采购时登记资产。计算含残值的直线折旧并接入 P&L 与 Dashboard。提供可复核的 AI 残值建议，并让应用的 AI 调用共用 Responses 或 Chat Completions 协议选择。

M20 支持一笔完整、已确认的采购 Expense 对应一项资产。多笔采购合并、采购拆分、跨年期初余额导入、资产处置、总账或资产负债表，以及联网查询残值行情留待后续。

## 冻结的产品与架构决策

### D1 · 采购与登记

- 「新增开支」和「收件箱审核」提供默认未选中的「登记为固定资产」。选中后展开资产名称、实际投用日期、使用年限、预计残值和用途类型。默认五年、公司本位币零残值和纯商用。混合用途在开始折旧前填写初始业务使用比例暂估值。投用日期留空时先登记为「待投用」，填入实际日期后开始折旧。
- 已保存的采购可用相同字段「转为固定资产」。确认前按报表期间展示原 Expense 贡献、新折旧和差额。已有的福禄克采购可以在购置当年从实际投用日起重算。原损益贡献或替代折旧若会影响以前自然年度的 P&L，阻止转换。已有采购逐笔确认转换。
- 保留原 Expense、原件归属和采购 VAT。资产接管损益确认，待投用的新资产也适用。原 Expense 的 VAT 与业务使用字段继续服务于既有 VAT 规则。在同一事务写入采购与关联资产，收件确认在该事务内一并转移原件。复用收件箱锁和文件版本检查。普通新增带资产时，以公司为范围绑定客户端提交 UUID，相同请求重试返回原结果，同一 UUID 配不同输入返回冲突。
- 保留采购成本快照及关联。普通 Expense 操作保护已关联采购的财务字段和删除入口。影响折旧或原采购的受控更正须先预览并留审计记录。原件和修订历史可追溯。

### D2 · 成本、折旧与年度台账

- 以已保存的本位币采购金额为成本基础，按既有采购税务类型计入适用的实际不可抵扣采购 VAT。复用采购成本基数逻辑和锁定的汇率快照。€450 用于录入提示，是否资本化由用户确认。 [荷兰税务局购置成本与低值资产说明](https://www.belastingdienst.nl/wps/wcm/connect/bldcontentnl/belastingdienst/zakelijk/winst/inkomstenbelasting/inkomstenbelasting_voor_ondernemers/investeren_in_bedrijfsmiddelen)。
- 采用直线折旧，年度基准额为 `（采购成本 − 确认残值）÷ 使用年限`。残值介于零与成本之间，年限为正整数。校验本里程碑普通设备适用的年度基准额 20% 上限。投用首月按实际使用天数折算，按月末分配，末期补足剩余比例及最小货币单位尾差。完整累计折旧等于采购成本减残值。台账可查看未来计划，P&L 和 Dashboard 将报表期间已到月末的折旧纳入计算。 [荷兰税务局折旧计算说明](https://www.belastingdienst.nl/wps/wcm/connect/bldcontentnl/belastingdienst/zakelijk/winst/inkomstenbelasting/inkomstenbelasting_voor_ondernemers/afschrijving/hoe_berekent_u_het_bedrag_van_de_afschrijving)。
- 按自然年展示来源采购、成本、预计残值、期初净值、当年及累计折旧、期末净值和用途状态。P&L 返回可独立识别的资产折旧，Dashboard 复用同一报表投影。未转换采购继续按原开支摊销规则处理。

### D3 · 混合用途与储能电池 VAT

- 纯商用资产按 100% 折旧计入 P&L。混合用途资产先按用户填报的当年暂估比例计入。后续年度在用户录入或确认该年比例前可沿用最近一个记录比例作为暂估。在台账、P&L 和 Dashboard 标注暂估。Q4 或之后确认实际值时，替换该自然年的暂估并重算受影响的月份和季度。更正留存前后值、原因、操作者和时间。台账分别展示完整折旧、私人使用扣减和损益净额，账面净值按完整折旧计算。
- 同一采购可同时关联一项固定资产和一项 [M16 电池记录](M16_zh.md)。支持任一登记顺序，双方均登记后共用投用日期。已有电池记录在转换时提供该日期。损益用的比例和 VAT 1d 年度私用比例分别确认。进项 VAT 仍通过原采购计入既有 5b，电池 VAT 调整沿用 M16 的基数与年度算法。
- 受控更正涉及共同采购基数或投用日期时，预览 VAT 和 P&L 影响并在同一事务更正两边。仅针对一边的年度修订只改变对应报表投影。沿用 M16 的重新确认和溯源规则。

### D4 · AI 协议选择与升级兼容

- 全局 AI 设置增加类型化 `api_protocol`，取值为 `responses` 和 `chat_completions`。显式保存的值优先，其次为显式配置的环境变量 `AI_API_PROTOCOL`。两者都缺省时，已有 AI 设置行或已有环境变量凭据的实例继续使用 Chat Completions，全新配置默认 Responses。旧 API 客户端省略字段时保留当前有效协议。沿用 Base URL、模型、启用状态、提示词、密钥存储和覆盖行为。读取响应和日志均不暴露密钥。
- 扩展 `GET/PUT /api/v1/settings/ai` 和 `POST /api/v1/settings/ai/test`。设置页展示有效协议。用合成图片测试未保存的表单覆盖值，测试与业务流程复用同一配置解析和调用实现。保存由管理员单独操作。所选模型或端点拒绝请求时，反馈当前协议和脱敏错误，由管理员修正配置或手动切换。
- 在已配置的 API 根地址追加 `/responses` 或 `/chat/completions`。Expense 直接附件、收件箱、外部销售、发票 PDF 核验和残值估计使用同一协议选择。沿用 PDF 转图和公共提示词及校验逻辑。Responses 采用无状态、非流式请求并发送 `store: false`，使用图像输入和供应商支持的结构化文本配置。从有类型的输出数组读取助手正文，显式处理拒绝、未完成和空输出。供应商明确拒绝所请求的 JSON 格式时，可在同协议省略该参数重试一次，仍执行应用解析器校验。协议错误不会触发另一协议的请求。 [OpenAI 官方迁移指南](https://developers.openai.com/api/docs/guides/migrate-to-responses) · [OpenRouter Responses API](https://openrouter.ai/docs/api_reference/responses/overview)。

### D5 · AI 残值估计

- 扩展既有采购识别响应，识别得到时提供可选的商品名称、品牌和型号。残值旁提供显式估计按钮。使用识别结果或用户手填的商品信息、服务端已校验的资产成本和年限，以及可选的状态或使用假设。此次估价仅发送上述字段，原件仍由原票据流程处理。
- 返回公司本位币的期末残值建议、简短理由和关键假设。后端校验结构及有限金额，金额介于零与采购成本之间。商品依据不足时返回资料不足状态。界面标识模型估计和不确定性。用户可采用、忽略或改写。商品、成本或年限变化时使旧建议失效。估计失败保留当前金额，保存以用户最后确认的表单值为准。

## 契约与数据模型

| 接口面 | 契约 |
| --- | --- |
| `/api/v1/fixed-assets` | 资产列表和详情，转换预览和确认，受控更正预览和提交，以及年度用途读取和确认。折旧计划和报表差额由后端提供。 |
| 新增开支和票据确认 | 接收同一个可选资产输入，成功时返回关联资产 ID。旧请求继续走原采购路径。 |
| P&L 与 Dashboard | 在现有响应增加固定资产折旧和暂估信息。开支报表继续展示基础采购记录。 |
| AI 设置与连接测试 | 通过现有类型化设置 API 和缓存服务增加协议选择。设置 JSONB 兼容缺少新键，无需为协议迁移数据库或回填密钥。 |
| 采购识别与残值估计 | 增量扩展 `ExpenseAIPrefill` 的可选商品信息。在固定资产 API 下提供已鉴权的估计端点，既有识别载荷可读。 |

用增量 Alembic 迁移增加公司所属的固定资产、年度用途和审计历史。采用 PostgreSQL RLS、同公司外键、唯一采购关联及适用的唯一持久化提交标识。金额采用 `Decimal`，在后端 services 层计算。契约变化后重新生成 OpenAPI TypeScript 类型。

## 原子任务卡

依赖顺序为 **1 → 2 → 3 → 4 → 5 → 6 → 7**。每步遵循[路线图 §5](../roadmap_zh.md#5-每个原子步骤的模板--definition-of-done)的质量门禁，使用隔离的验证资源。编排模式下每步在 `review-notes/M20-step<n>-impl.md` 写中文实施简报，记录实际命令和结果、未执行项及可复现走查。里程碑完成后写 `review-notes/M20-report.md`。报告保存在本地并由 Git 忽略。

### Step 1 · 折旧计算与转换预览

- **目标／输入** 按 D1–D2、M8.5 字段及 M10 报表口径交付已有采购的只读转换预览。
- **后端／契约** 锁定资产输入、月度与年度折旧和转换差额契约，使用 Decimal 计算。
- **前端／迁移** 从开支详情展示原摊销、新折旧和差额。无需迁移。
- **必测范围** 零和非零残值、首年部分时间、闰年、舍入、无效年限及超成本残值。
- **盲审点** 月度和年度合计与期末净值对账，预览无写入。

### Step 2 · 已有采购转入与年度台账

- **目标／输入** 基于 Step 1 和 D1–D2，交付纯商用资产确认和年度台账。
- **后端／迁移** 增加受 RLS 保护的资产记录和采购关联。确认时锁定 Expense 并复核预览。保护已关联的财务字段，折旧进入共用 P&L 计算。
- **前端** 增加资产导航、年度列表和详情，展示账面值和来源采购链接。
- **必测范围** 福禄克同年转换、以前年度保护、月末归期、重试、并发、回滚、公司隔离、采购 VAT 及原件。
- **盲审点** 原损益贡献只替换一次，P&L、Dashboard 与台账对账。

### Step 3 · 混合用途与储能电池联动

- **目标／输入** 基于 Step 2 和 M16 电池登记交付 D3。
- **后端／迁移** 增加年度暂估、确认和审计修订，支持两种登记顺序及共同基数的原子更正。
- **前端** 展示暂估金额、确认差额和修订历史，提供电池 VAT 登记入口。
- **必测范围** Q4 确认后重算 Q1–Q3、比例按年独立、两种登记顺序、共同更正对账，以及损益和 VAT 私用分别修订。
- **盲审点** 每笔业务只在对应自然年度和报表中贡献一次。

### Step 4 · 新增开支直接登记固定资产

- **目标／输入** 在普通采购新增和收件箱确认中复用 Step 2–3。
- **后端／契约** 接收统一的可选资产输入。普通新增使用提交重放，收件箱沿用文件版本检查。采购、资产和适用的原件转移一次提交。
- **前端** 增加资产勾选项、默认值、待投用显示和已保存资产链接。
- **必测范围** 未勾选、两个勾选入口、默认及手填残值、待投用、重复提交、过期文件版本和失败回滚。
- **盲审点** 一次确认只创建一笔采购和一项资产，失败后可恢复表单审核。

### Step 5 · Responses 与 Chat Completions 协议切换

- **目标／输入** 在现有 AI 调用方实现 D4，同时保护旧实例升级行为。
- **后端／契约** 增加协议设置、统一的协议选择和合成图片连接测试。处理两种协议的图像载荷、正文解析和供应商错误。
- **前端／迁移** 增加协议选择、双语提示和未保存测试。旧设置和密钥可直接读取，无需回填。
- **必测范围** 全新、旧版和仅环境变量配置、显式覆盖、省略字段、切换与切回、图像和 JSON 请求、拒绝、截断、异常输出和端点不支持。用隔离配置通过 OpenRouter Responses 识别合成票据。
- **盲审点** 设置、探测和实际请求采用同一协议。无跨协议自动重试，无凭据或票据内容泄露。

### Step 6 · AI 残值估计

- **目标／输入** 使用 Step 5 的传输与 M19 采购识别交付 D5。
- **后端／契约** 增加可选商品识别和估价调用，校验输出并处理资料不足。
- **前端** 展示残值建议、理由和假设，允许显式采用，保留手工输入及用户修改。
- **必测范围** 票据和手填输入、采用、忽略、编辑、资料不足、无效金额、超时、过期结果、两种协议，以及既有识别和 VAT 建议回归。
- **盲审点** 估价不会入账，保存的残值来自用户确认表单。

### Step 7 · 回归、部署走查与验收

- **目标／输入** 依据已完成的任务卡和下列清单端到端验证 D1–D5。
- **回归与门禁** 执行 Ruff、严格 Mypy、pytest 与隔离 PostgreSQL 集成、前端测试和构建、OpenAPI 类型无漂移检查及 Docker build。分别记录真实供应商测试与受控响应测试。
- **盲审点** 对账各登记入口、历史转换、报表投影、协议升级及人工回退。区分自动化完成与作者验收。
- **文档／报告** 按实际交付更新双语路线图及功能文档，保留历史验收证据。完整走查写入 `review-notes/M20-report.md`。

## 部署自测与验收

使用默认 dev Compose 命令 `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d`，配合隔离的样本和 AI 配置。

1. 录入一笔类似福禄克的当年采购，先按既有 Expense 五年摊销，再预览并确认转换。核对差额、原 VAT 与原件、各期 P&L、Dashboard，以及折旧到期前的账面净值。
2. 直接新增一笔默认零残值资产，再试一笔有手填残值、未填投用日的采购。确认台账显示待投用，填写实际投用日期后核对月末折旧。
3. 在收件箱审核合成储能票据。估计残值并查看理由，走查采用和修改建议。确认一次采购和资产，核对原件、5b、M16 年度调整、暂估 P&L 及 Q4 确认后早期季度的变化。
4. 用已配置 Chat Completions 的样本升级。保存前测试 Responses，使用兼容模型切换并识别合成票据，再切回。核对全新配置默认 Responses，供应商不可用时可手工完成。
5. 记录作者走查或作者明确委托的等效验收，并列出跳过项。走查后记录部署验收状态。

## 验收结论

🟢 作者于 2026-11-24 按记录的开发环境走查范围验收 v0.16.0。七个实施步骤均通过隔离本地门禁和独立审查。走查复用既有开发库，迁移从 `0058` 到 `0061`。

- **普通采购。** 转换已保存采购，核对原件、€252 进项税、第一季度 €40 折旧和年初至今 €180 折旧，对账损益及仪表盘。直接新增走查了默认零残值、待投入使用及残值 €100 的资产投用。
- **真实 OpenRouter Responses。** 升级后旧配置解析为 Chat Completions。保存前 Responses 测试成功，保存后识别了一张合成采购票据。作者跳过人工切回 Chat Completions 和关闭 AI 后的手工入账。两项均有受控回归覆盖。
- **储能电池。** 模型先对合成票据提示资料不足，补充产品信息及测试假设后给出 €180 残值建议。正式采购保留 €180 残值和原件。单独的受控浏览器验证确认，手动编辑为 €120 时，表单提交采用手填值。核对 2026 年实际业务使用 75% 与先前 50% 的快照，Q1–Q3 每季业务折旧从 €25.50 增至 €38.25。单独确认的 M16 VAT 维持 45% 私用，Q4 1d 计税基础 €108、VAT €22.68，原采购 Q1 5b 进项税 €252。
