## Goals & Scope

**Goal**: manually select and order PDF appendices for a Quote, then preview, download and email one complete PDF containing the quotation followed by those appendices.

**IN**:
- A company-private reusable PDF library inside the existing Content Library.
- Quote-specific PDF uploads that are unavailable to other Quotes.
- A saved, ordered appendix selection in the Quote editor, with file preview/download and clear unsaved-change handling.
- Lossless page-level assembly in the sense of retaining text/vector page content, dimensions and orientation rather than rasterizing pages; the combined file is newly serialized, not byte-identical to its inputs.
- Immutable original files, library archiving/restoration, accepted-Quote read-only behavior and omission-compatible Quote API changes.
- Consistent preview/download/email composition, limits, actionable failures, tenant isolation and bilingual UX.

**OUT / deferred**:
- Product associations, automatic recommendations or automatic selection when adding products.
- Invoice/Estimate/payment-receipt appendices, attachment propagation during conversion, or appendix copying during Quote duplication.
- Separate brochure email attachments, per-send overrides, ZIP exports or public file links.
- Divider pages, cover sheets, automatic contents pages, global page numbering, page resizing or brochure editing.
- In-app history of exact sent Quote PDFs, Quote revision chains, replacement of retained formal artifacts or changes to M12/M13 retention.
- Folder/tag/category systems, automatic language selection, full library version management, OCR/AI extraction, external URL imports, bulk uploads, physical library-file deletion or cleanup jobs.
- Content/report generation and unrelated address/routing integrations.

**Related foundations**: [roadmap](../roadmap.md), [M6](M6.md) Quotes/content, [M9](M9.md) PDF/email, [M12](M12.md)/[M13](M13.md) retained formal PDFs and [SI1](../improvements/SI1.md) ordering, duplication and server-side Sent copies. This milestone changes no pricing, numbering, VAT, exchange-rate or report calculations.

## Frozen Product & Architecture Decisions

### D1 · The selection belongs to the Quote

Add an **Appendices** section at the end of the existing Quote editor, before the save actions. Users select library files, upload Quote-specific files, preview/download originals, drag to reorder and remove selections. Show title, source, original filename, page count and size. Do not select any file automatically from a product or customer.

The saved selection is shared by all subsequent preview/download/send actions. Selection, removal and order changes participate in the existing dirty-state snapshot and unsaved-change guard. Removing an entry deselects it; it does not delete the original. Duplicate file IDs in a selection are invalid. Identical bytes uploaded as different file records are allowed; no automatic content deduplication is introduced.

### D2 · Company-private reusable library

Add a **PDF Materials** tab to Content Library, not a separate top-level navigation item. Support upload, title search, pagination, original preview/download, title editing, archive and restore. Show active files by default and allow archived files to be viewed. A shared library means reuse inside the authenticated company, not internet-public access.

Original bytes, original filename, hash, size, page count and ownership are immutable. Upload a new file to publish a replacement; archive the old file separately. There is no replace-in-place endpoint or physical library deletion. Renaming or archiving never changes an existing Quote's file or its selected-title snapshot. Newly selected entries snapshot the current title on save.

An archived file can remain or move within the same Quote's persisted selection. It cannot be newly selected on another Quote or re-added after its removal has been saved, until restored. Determine this from persisted membership, not a client flag. Restoring makes it selectable again without rewriting any Quote.

### D3 · Quote-specific upload and save semantics

Quote-specific uploads require a persisted Quote. On a new Quote, the upload action offers **Save and continue**: validate/save the current form, stay in its editor at the persisted ID, then continue to upload. If save fails or is cancelled, do not upload. Keep the ordinary Save button's current return-to-list behavior.

Uploading stores the file as available to that Quote and adds it to the browser's pending selection; it does not change the persisted selection. Only a successful Quote save commits selection and order. If the user abandons the editor afterwards, the already uploaded file remains in that Quote's own-file picker and can be selected later. No temporary anonymous upload or expiry mechanism is required.

Quote-specific originals remain until normal Quote deletion; deselection is not deletion, and there is no separate file-delete or promote-to-library command in v1. They cannot be selected for another Quote. Uploading an own file does not increment the saved selection version.

### D4 · Lifecycle, duplication and conversion

Follow existing Quote editability: **ACCEPTED is read-only**, while other states retain existing edit rules. Accepted Quotes allow appendix viewing and original downloads, but no uploads, selection changes or reorder. Do not introduce a new accepted-Quote reactivation transition.

**Duplicate Quote always starts with an empty appendix selection and no copied own files**, irrespective of source status. Conversion to an Invoice leaves the original Quote's appendices in place and attaches none to the Invoice. These are intentional, narrow additions to existing duplication/conversion behavior; other copied fields and financial semantics remain unchanged.

### D5 · One complete output

Keep existing WeasyPrint quotation rendering and add `pypdf` for page assembly. Use a new writer to append the quotation followed by every selected file, in saved order. Preserve page dimensions, rotation and printable content; do not rasterize, rescale, add divider pages or overlay quotation furniture on brochures. See [pypdf merging](https://pypdf.readthedocs.io/en/stable/user/merging-pdfs.html) and [PdfWriter](https://pypdf.readthedocs.io/en/stable/modules/PdfWriter.html).

Preview and download use the same existing Quote PDF endpoint; sending calls the same composition service. Without appendices, retain the current rendering path without a merge pass or new appendix-specific output limits. Filename and locale resolution remain existing behavior. Only the quotation body changes language; uploaded brochures are not translated or switched automatically.

The final email contains **one** PDF attachment. Build it completely before SMTP, and pass the same generated attachment through SMTP and the existing optional Sent-copy path. Do not render independently for Sent copying or add source PDFs as extra attachments. Separate preview/download/send requests need not produce byte-identical PDFs because the existing renderer may include variable metadata.

### D6 · Explicit output failures; no silent omission

If any selected original is missing/unreadable, fails its stored hash check, cannot be merged, or exceeds limits, stop the whole output and return a stable error with the failing file ID where applicable. The UI maps the ID to its visible title. Never fall back to quotation-only output or omit a broken appendix.

Composition failure happens before any SMTP attempt and does not create a successful send or change business status. Actual send failures and Sent-copy failures retain existing email-log semantics, including no automatic retry and SMTP success remaining success when only Sent copying fails. Do not log PDF bytes, extracted content, unsafe parser messages or email credentials.

Keep original files stable, but do not claim that this freezes the quotation body or retains exact historical outgoing Quote PDFs. Existing email logs and optional provider Sent copies remain the only existing mail-traceability behavior in this milestone.

### D7 · Two additive tables; transactional originals

Use PostgreSQL `LargeBinary`/`BYTEA` for appendix originals, following the existing database-binary retention pattern. This gives transactional file/metadata writes and database-managed deletion without filesystem cleanup races. Do not extend `DocumentArtifact` or reuse its invoice/refund ownership and output fingerprint semantics. Database backups must include these new tables; no new storage volume is needed.

| Table / field | Definition |
| --- | --- |
| `pdf_appendix_file` | UUID `id`, `company_id`, nullable `owner_quote_id`, `title` TEXT, immutable `original_filename` TEXT, `pdf_bytes` BYTEA, `sha256`, `size_bytes`, `page_count`, `is_archived`, timestamps |
| Ownership | `owner_quote_id IS NULL` means company library; otherwise a Quote-specific original. Ownership cannot be reassigned. Own files cannot be archived; archive/restore applies only to library files. |
| `quote_appendix` | UUID `id`, `company_id`, `quote_id`, `file_id`, `sort_order`, `title_snapshot` TEXT; unique `(quote_id, file_id)` and `(quote_id, sort_order)` |
| Quote extension | Non-null integer `appendix_version`, default/backfill `0`; existing Quotes start with empty selections. |

Both new tables use existing PostgreSQL RLS conventions and server-derived ownership. Services validate that a file is either same-company shared material or owned by this exact Quote. A Quote cannot acquire another company's or another Quote's own file by guessing a UUID.

Use DB foreign keys and ORM cascade: deleting a Quote removes its `quote_appendix` rows and its own file rows, while leaving library files intact. File-reference constraints must permit that one transaction without depending on cascade ordering (use a deferred file-reference check). Prevent deletion of a still-referenced shared file. Do not implement manual child-delete loops, file-delete hooks or hash-based sharing of own-file records across Quotes.

Never return `pdf_bytes` in JSON. Read/list metadata queries must not eagerly load blobs. The server selects UUIDs, hashes and size/page metadata; clients cannot supply ownership or trusted validation results.

### D8 · Concurrency and compatibility

- Extend `QuoteWrite` with ordered `appendix_file_ids` and `expected_appendix_version`; extend `QuoteRead` with `appendices` and `appendix_version`. Pricing-calculation requests do not gain file fields.
- On create, omitted selection means empty; a nonempty list can reference active company-library files only. Initialize version to `1` for a nonempty saved selection, otherwise `0`.
- On update, omission preserves selection/version; an explicit empty list clears it. Explicit `null` is invalid. Providing the list requires an expected version, even if its content is unchanged. Increment only when saved membership/order changes; preserve title snapshots for unchanged members and take a new snapshot for new members.
- Save the quotation and selection in one transaction. Validate file eligibility and limits before replacing the saved selection. A failed or stale appendix save must not partly save quotation fields.
- Lock the same parent Quote row for writes, own-file uploads and acceptance; recheck accepted state after obtaining the lock. Perform archive/restore eligibility checks under file-row locks, acquired in stable ID order after the Quote lock when applicable.
- Output must materialize one coherent quotation/selection/original snapshot before rendering. Parent-row locking must serialize relevant Quote updates, deletion and acceptance against that read; do not perform separate unlocked reads that mix versions. Release the snapshot lock before SMTP network work.
- Existing callers omitting appendix fields retain current behavior. Duplication explicitly starts empty, and old Invoice/receipt artifacts remain untouched. Do not turn the appendix version into a new global Quote revision or alter financial calculations.

### D9 · File validation, safety and limits

Accept ordinary static PDFs only. Bounded streaming multipart must reject oversized data before general-purpose upload spooling can consume an unbounded body; reuse/extract the bounded M13 upload technique without changing its exact-byte artifact contract. Authenticate and resolve the target before file processing; recheck lifecycle during the upload transaction.

Validate declared MIME, PDF header, nonempty content, parseability, all page access and a successful safe page-copy/write. Reject encrypted PDFs (including empty-password encryption), digital signatures and fillable/XFA forms. Do not silently flatten or promise interactive/signature preservation. Retain accepted original bytes exactly.

Composition creates a fresh document rather than cloning a source catalog. Do not import scripts, automatic/additional actions, launch actions or embedded files. Sanitize page/annotation actions: retain ordinary `http`, `https` and `mailto` links; reject or strip other actions, including file/JavaScript links, while retaining static page content. If a source cannot be handled safely, reject it on upload. Original preview/download remains authenticated; do not serve uploaded HTML or execute/fetch PDF-linked resources. Titles/filenames are untrusted display data and require escaping and safe response headers.

| Typed backend configuration | Default |
| --- | --- |
| `max_appendix_file_bytes` | `10 * 1024 * 1024` (10 MiB) |
| `max_quote_appendices` | `10` files |
| `max_quote_appendix_input_bytes` | `15 * 1024 * 1024` (selected originals combined) |
| `max_quote_pdf_bytes` | `15 * 1024 * 1024` (combined output) |
| `max_quote_pdf_pages` | `200` (quotation plus appendices) |

Reject an individual original over the page limit at upload; enforce selection count/input bytes and selected-original page bounds on save, and full page/output-byte limits after composition. Bound the upload-time rewritten candidate too. Read the configured limits through a typed API; do not duplicate numeric policies in Vue or couple them to receipt/artifact limits. Explain that email encoding increases attachment size and the provider may impose a smaller mail limit.

Run synchronous PDF parsing/assembly off the async event loop using bounded worker concurrency; use request-local readers/writers and close resources on every path. This adds no background queue. Do not change the existing PDFium AI/receipt processing pipeline or make unrelated parser/threading refactors.

## Contract (Define First)

All paths below are under `/api/v1`, use the existing MFA owner guard and RLS. Lists use the project's `limit`/`offset` and total-count convention. Define Pydantic models/OpenAPI before implementation, and regenerate `schema.d.ts` in each contract-changing step.

| Method / route | Input → output / behavior |
| --- | --- |
| `GET /pdf-library/limits` | `200 PdfAppendixLimitsRead`, with the five configured numeric limits in D9 |
| `GET /pdf-library` | Optional title `search`, `include_archived=false`, pagination → `200 PdfAppendixFileListResponse`; active only unless requested otherwise |
| `POST /pdf-library` | Bounded multipart: required `file`, optional nonblank `title` (default original filename) → `201 PdfAppendixFileRead` |
| `PATCH /pdf-library/{file_id}` | `PdfLibraryFileUpdate`: optional nonblank `title`, optional `is_archived`; no bytes or ownership fields → `200 PdfAppendixFileRead` |
| `GET /pdf-files/{file_id}/content` | Optional `disposition=inline\|attachment`, default `attachment` → authenticated `application/pdf` bytes with safe original filename |
| `GET /quotes/{quote_id}/appendix-files` | Paginated Quote-specific originals, including currently unselected files → `200 PdfAppendixFileListResponse` |
| `POST /quotes/{quote_id}/appendix-files` | Same bounded upload fields → `201 PdfAppendixFileRead`; no persisted selection change |
| Existing `POST /quotes`, `PUT /quotes/{id}` | Add D8 selection/version fields; return extended `QuoteRead` |
| Existing `GET /quotes/{id}` | Add ordered `QuoteAppendixRead[]` and `appendix_version`; do not expand collection-list summaries with file blobs |
| Existing Quote PDF and send routes | Keep request shapes and successful response types; use composed output and declare composition errors |

`PdfAppendixFileRead` exposes ID, computed `source=LIBRARY|QUOTE`, owner Quote ID where applicable, title, original filename, SHA-256, byte size, page count, archive state and timestamps. `QuoteAppendixRead` exposes association ID, file ID, saved order/title snapshot and file metadata. JSON never contains blobs. Library PATCH applied to a Quote-owned file returns `404`.

Stable errors: `404` for missing/cross-company/foreign-own-file references; `409` for accepted-Quote mutation (`QUOTE_APPENDICES_READ_ONLY`), stale selection (`QUOTE_APPENDIX_VERSION_CONFLICT`) or newly selecting an archived file (`PDF_LIBRARY_FILE_ARCHIVED`); `413` for file/input/output byte limits; `422` for malformed/unsupported PDFs, duplicate IDs, count/page limits or invalid requests. A stored-file/merge failure returns a safe `500 QUOTE_PDF_COMPOSITION_FAILED`, with `file_id` only when known. Return a stable `detail.code`; do not expose raw exceptions or paths. No file or composition failure is an SMTP attempt.

## Data Models / Migrations

- Step 1 adds both tables, RLS/grants, indexes and FK/unique/check constraints; Step 3 adds/backfills `Quote.appendix_version`. Original bytes and metadata are inserted atomically.
- Require positive byte/page counts and nonnegative contiguous saved order; enforce unique file/order membership, valid same-Quote ownership and the D7 cascade behavior. Nullable owner is the library/own distinction, not a collection of unrelated nullable business FKs.
- Use additive migrations from the actual current `main` head when implementing. Do not rewrite released migrations, reserve numbers on the paused M15 branch or add revision collisions.
- Upgrading creates no files or selections, changes no old PDF/email record and triggers no rerender/backfill. A normal database backup includes new originals; no filesystem garbage collection or automatic data migration is part of this feature.

## 🟢 Deployment Self-Test Points (Milestone Acceptance)

Start the normal development stack with `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d`; use test PDFs and a recipient chosen by the author.

1. Open Content Library → PDF Materials. Upload two static PDFs, including a landscape/non-A4 example and a Chinese filename. Check title search, limits, page counts, preview and downloaded-original SHA-256. Change a title, archive and restore; verify other content tabs still work.
2. Create a Quote. Select a library file, then invoke own upload. Use Save and continue; verify one saved Quote, unchanged form content and the same editor, then upload a third PDF. Save the mixed selection in a deliberately different order and reload.
3. Preview and download the complete Quote. Confirm body first, correct appendix order/content/dimensions/orientation, no extra divider or overwritten brochure footer. Switch quotation language; brochures stay unchanged. Check a no-appendix Quote separately.
4. Change the selected library title and archive that file. Reload the original Quote and verify its title snapshot/file still appear and output works; new selection cannot add the archived file. Upload a replacement and confirm old Quotes still use original bytes.
5. Upload another own file but leave the selection unsaved. Exercise the leave/cancel/save prompt. Reopen the Quote; the original saved list is intact and the newly uploaded own file is available for reselection. Remove a selected file, save and verify it is excluded from complete output without deleting its original.
6. Send to the author's test recipient, optionally with CC and Sent copying. Verify one complete PDF attachment at the recipient and the provider Sent folder where enabled. Automatic tests cover failure variants not safely exercised against a real provider; record these separately.
7. Duplicate a Quote with both file sources. Verify empty appendices and no copied own files, with existing duplication fields unchanged. Accept the original; verify upload/edit/reorder blocked but viewing/output still work. Convert using an eligible test workflow; the Invoice has no appended brochure and the source Quote retains its selection.
8. Exercise invalid/encrypted/form PDF and a configured limit boundary; errors identify the issue without leaving partially saved state. In two editor sessions, save two conflicting selections and verify the second cannot silently overwrite the first.
9. Delete an eligible disposable Quote with own files and shared selections; confirm its own files/associations disappear while library files and another Quote's selection survive. Use isolated runtime-role tests for second-company isolation and cascade races when not manually exercised.
