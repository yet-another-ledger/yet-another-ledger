## Product and Technical Decisions for This Round (Finalized with Author Before Starting · 2026-06-13)
- [x] **D1 · AI credential storage = mirror SMTP pattern**: `SETTING_KEY_AI = "ai"`, GLOBAL level, `AiSettings { enabled: bool, base_url: str, api_key: str, model: str }` stored plain in JSONB; read returns `AiSettingsRead { enabled, base_url, api_key_set: bool, model }` masked (only `api_key` hidden); `services/ai.py` follows "DB settings → env fallback (`config.ai_base_url` / `ai_api_key` / `ai_model` / `ai_enabled`)". **No at-rest encryption** (isomorphic with existing SMTP). `base_url` default `https://api.openai.com/v1`, user-overridable.
- [x] **D2 · Receipts = disk storage abstraction, no thumbnails**: Create `services/storage.py` (`LocalStorage`, root `config.storage_root`, size limit `config.max_receipt_bytes`, MIME whitelist = images + PDF), `expense_attachment` stores metadata + storage key; **don't go into `binary_asset` bytea**; no thumbnails (serve original file). Share storage interface with M9 PDF.
- [x] **D3 · Recurring expense generation as draft awaiting confirm**: Scheduled job clones `is_draft=true` expenses; user confirms / attaches receipt in list to commit (`is_draft=false`). **Idempotent** (generate once per period), pausable, can set limits (count / end date).
- [x] **D4 · AI price-list follow-on is a separate standalone round**: M8 main line (expense CRUD + receipts + recurring + AI receipt fill + frontend closure) closes and passes acceptance first; price-list → catalog recognition reuses AI pipeline as a separate post-M8 round (not counted in M8 acceptance).
- [x] **D5 · AI call shape = synchronous + prefill no-persist + failure fallback hand-fill**: `POST /expenses/ai-extract` synchronously calls vision model, returns `ExpenseAIPrefill` for frontend preview only; user confirms then normal `POST /expenses` persists. AI off / call failure → return clear signal; frontend falls back to manual fill.
- [x] **D6 · AI client = OpenAI-compatible Chat Completions, self-constructed with `httpx`, no vendor SDK (author decided 2026-06-13)**: **Don't use `anthropic`, don't use `openai` SDK, don't use `requests` (sync blocks async), don't hardcode any provider/model**; `base_url`/`api_key`/`model` all user-configured in settings (can point to OpenAI / OpenRouter / local vLLM etc.). Client directly `httpx.AsyncClient` `POST {base_url}/chat/completions`, request/response use custom small Pydantic models; `httpx` promoted from dev to **main dependency**. **Calls must be injectable / mockable** (`respx`/`MockTransport`); unit tests don't hit real network. Multi-modal via `image_url` (base64) — **images send directly; PDF backend rasterizes then sends** (see D16), three receipt types one path. Rationale: call surface tiny and stable, async-native, provider-agnostic = HTTP contract not SDK, one fewer churn-prone dependency.
- [x] **D14 · AI settings include connectivity + multi-modal test** (author decided 2026-06-13): `POST /settings/ai/test` mirrors SMTP test — backend uses config `httpx` to actually send one small-image Chat Completions probe, returns `{ ok, multimodal, detail }`, confirming connectivity + model accepts image input; frontend settings page has "test" button. **Probe image is built-in tiny image (no user data sent externally); key not in response/logs.**
- [x] **D15 · Prompt configurable (default + user override · author decided 2026-06-13)**: `AiSettings.receipt_prompt` (GLOBAL, user-editable in settings); empty → falls back to code constant `DEFAULT_RECEIPT_PROMPT` (includes Dutch receipt/BTW context). **User only edits the "extraction instructions"; output JSON field contract is system-fixed appended and non-editable** (`_OUTPUT_CONTRACT` footer), keeping parsing robust; parser fully fault-tolerant (`ExpenseAIPrefill` all fields nullable). Model returns only **category text name**; service side best-effort matches by name to company's `category_id`; don't let model guess VAT treatment (leave to user, default `NL_DOMESTIC_PURCH`). No migration (uses existing `setting` JSONB).
- [x] **D16 · PDF receipts = backend rasterize to image, uniform image_url path (author decided 2026-06-13 · reverses earlier "PDF→AI deferred")**: `ai-extract` **normalizes all inputs to images** before feeding model — `image/*` use directly; `application/pdf` use **`pypdfium2`** (self-contained pre-compiled wheel, **no system poppler**, BSD/Apache license) page-by-page `render()` → `Pillow` encode PNG/JPEG → base64 into `image_url` (each page one part; page limit `config.ai_pdf_max_pages` default 3; render scale/DPI configurable). **Electronic PDF and scanned PDF treated identically** (scanned rasterization just retrieves that scanned image). **Rationale**: `image_url` is the only provider-agnostic path; model "sees" image better than text extraction, doesn't lose layout; one path / one prompt / one parser. New deps `pypdfium2` + `Pillow` (pure wheel, no system packages; not `pdf2image` [needs poppler] / `PyMuPDF` [AGPL]). Genuinely unsupported MIME → `422`.
- [x] **D7 · Input VAT reuses `vat_treatment` (PURCHASE-side) + `vat_rate`**: No separate expense-side enum (red line 12). Treatment FK `RESTRICT` + snapshots code/label/effect; rate FK `RESTRICT` + snapshots percent/label (mirrors `invoice`).
- [x] **D8 · Net + VAT both authority entry values, no forced `vat == net × rate`**: Real receipts round each line independently; totals commonly differ from `net×rate` by a few cents. Therefore store net and VAT both exactly **as-given** (receipt/AI gives to-cents values); backend only calculates `gross = net + vat` then quantizes to cents; **no equality validation** (`vat_rate` only serves as reporting category / display reference, not calculation driver).
- [x] **D9 · Deductible default from category, per-line overridable**: `ExpenseInput.deductible` omitted → use `expense_category.default_deductible` (further fallback → `true`); explicit value takes precedence.
- [x] **D10 · Single base currency** (same as M5/M7): `currency = company base_currency`, `exchange_rate = 1`, `base_net/base_vat/base_gross = original values`; non-base-currency amounts rejected by backend (`422`). FX placeholder additive later.
- [x] **D11 · All amounts `Decimal`/`NUMERIC(18,3)`, persisted to cents** (red line 1 + M7.5): Entry net/vat `quantize_to_minor_unit` (EUR=2 digits) before persisting; `gross = quantize_to_minor_unit(net + vat)`. **Money-math logic must have unit tests.**
- [x] **D12 · Category FK `SET NULL` + name snapshot; delete expense cascades delete attachments + disk files** (red line 3): `expense.category_id` `SET NULL` (nullable; required by business at create time; name snapshot preserves history after dict item deleted); `expense_attachment.expense_id` `ON DELETE CASCADE`; plus **service deletes disk files when deleting expense** (DB cascade only clears metadata rows).
- [x] **D13 · AI settings UI in gear panel**: Reuse M2.5 "future AI expansion" slot (gear → AI category); don't create new entry.

## Money-Math and Split-Storage Rules (M8 Locked · `services/expense`)
> Schema only validates shape; all amounts / snapshots / defaults calculated by service. **Unrelated** to M5 tax engine (expenses don't recalculate tax; net/VAT stored as given on receipt).

- **Split storage (§7.4.1)**: `net_amount` and `vat_amount` both **authority entry values**; each `quantize_to_minor_unit` (EUR=2 digits, D11) before persist. **No validation that `vat == net × rate`** (D8).
- **Total**: `gross_amount = quantize_to_minor_unit(net_amount + vat_amount)`.
- **Deductible default (D9)**: `deductible` omitted → `expense_category.default_deductible`; further fallback → `True`; explicit value takes precedence.
- **Snapshots (D7/D12)**: At persist time snapshot `category_name` (FK `SET NULL`), `vat_treatment_code/label/effect` (FK `RESTRICT`), `vat_rate_percent/label` (FK `RESTRICT`) — deleting dict items doesn't corrupt history.
- **Single base currency (D10)**: `currency = company.base_currency`, `exchange_rate = 1`, `base_net_amount=net_amount`, `base_vat_amount=vat_amount`, `base_gross_amount=gross_amount`; request implying non-base-currency → `422`.
- **Validation**: `net/vat ≥ 0`; `category_id`/`vat_treatment_id`/`vat_rate_id` must belong to this company and `vat_treatment.side == PURCHASE` (SALE-side treatment used for expense → `422`).

## Storage Abstraction (M8 Locked · `services/storage.py` · Shared with M9)
> Red line 7 (path traversal prevention / input sanitization) + red line 9 (don't open inbound control endpoints).

- **Interface** (minimal set, reusable by M9 PDF): `save(namespace: str, key: str, content: bytes, content_type: str) -> str` (returns opaque storage key) / `open(key) -> bytes` (or stream) / `delete(key)` / `exists(key)`.
- **`LocalStorage` implementation**: Root = `config.storage_root` (container default `/data/storage`; dev default `./var/storage`; **separate volume from DB / frontend build artifacts**); layout `receipts/{company_id}/{expense_id}/{attachment_id}.{ext}`; **normalize and validate path is under root before write** (reject `..` traversal); filename uses only controlled UUID + whitelist extension; **don't trust client filename** (store display-only in DB).
- **Upload validation** (mirrors `services/assets.py`): MIME whitelist = `image/png`, `image/jpeg`, `image/webp`, `application/pdf`; size limit `config.max_receipt_bytes` (default 10 MB); double-check by **actual magic bytes / Content-Type**, reject spoofed.
- **Delete consistency**: When deleting attachment / expense, service calls `storage.delete(key)` in same logical unit as DB row delete; disk delete failure logs but doesn't block DB transaction (orphan files handled by later cleanup; DB consistency takes priority).

## AI Receipt Pipeline (M8 Locked · `services/ai.py` · OpenAI-Compatible Chat Completions)
> Red line 5 (typed settings for credentials) + red line 9 (don't open self-update/control endpoints) + red line 7 (treat receipt images as untrusted input).

- **Client (D6) = `httpx` (async), no vendor SDK**: Direct `POST {base_url}/chat/completions` (OpenAI-compatible contract); messages body includes text + multi-modal `image_url` (base64 data URL); reads `choices[0].message.content`. **`base_url`/`api_key`/`model` all from config; don't hardcode any provider/model id.** Custom small Pydantic models define **request body + response subset** (mypy-friendly); **HTTP calls injectable / mockable** (service accepts `httpx.AsyncClient` or factory); unit tests use `respx`/`MockTransport`, **never hit real network**. Timeout/error mapping self-controlled (connection failure → `502` + recoverable signal). **Rationale**: call surface tiny and stable, async-native (httpx already in stack), provider-agnostic = HTTP contract not SDK, one fewer churn-prone dependency.
- **Credentials (D1)**: `_get_ai_config(session)` = DB `SETTING_KEY_AI` → env fallback (`config.ai_base_url`/`ai_api_key`/`ai_model`/`ai_enabled`), mirrors `services/email.py::_get_smtp_config`. **Key never in logs, never in any response body / `ExpenseAIPrefill` / `AiTestResult`**; `AiSettingsRead` only returns `api_key_set: bool`.
- **Prompt (D15 · configurable)**: Final user-message text sent to model = `(settings.receipt_prompt or DEFAULT_RECEIPT_PROMPT)` + **system-fixed appended output contract footer** (`_OUTPUT_CONTRACT` constant, enumerating JSON keys our parser depends on, requiring "only return one JSON object; omit keys you can't recognize"). **User can only edit the extraction instructions part; output JSON contract is non-editable** — so changing prompt can't break parsing. `DEFAULT_RECEIPT_PROMPT` is a repository constant (includes Dutch receipt/BTW context hints). Optional: include `response_format={"type":"json_object"}` if endpoint supports it, but don't hard-depend (parser is fault-tolerant anyway).
- **Normalize input to images (D16)**: `_attachment_to_images(attachment, bytes) -> list[image_bytes]` — `image/*` returns `[bytes]` directly; `application/pdf` uses `pypdfium2` page-by-page `render(scale=…)` → `Pillow` encode (max `config.ai_pdf_max_pages` pages); other MIME → `422`. **Electronic and scanned PDFs treated identically**.
- **Extraction flow (D5)**: `extract_from_attachment(session, company_id, attachment_id)` → get this company's attachment (cross-company `404`) → if AI `enabled=false` / no key → clear error (frontend falls back to manual fill, don't raise 500) → read storage file → `_attachment_to_images` (non-image non-PDF → `422`) → each image as base64 into one `image_url` part + effective prompt → call model → **fault-tolerant parse** (strip code fence, `json.loads`, best-effort convert each field to `Decimal`/`date`, ignore unknown keys, **all fields nullable**) → service side best-effort match model's returned category text to company `expense_category.id` (no match → return text only) → compose `ExpenseAIPrefill` (parse failure/timeout → `502` + recoverable signal) → **return; don't persist**. Don't let model guess VAT treatment (cross-border classification unreliable); leave to user, default `NL_DOMESTIC_PURCH`.
- **Test probe (D14)**: `test_ai_config(cfg)` → use config `httpx` to send one **built-in tiny image** (fixed few-dozen-byte PNG in repo, **no user data sent**) + short text (e.g. "reply OK") Chat Completions request → normal response ⇒ `{ok:true, multimodal:true}`; auth/connection failure, model not found, model rejects image ⇒ `ok`/`multimodal` set false accordingly + `detail` reason. Called by `POST /settings/ai/test`.
- **Security**: Treat receipt images as untrusted; validate range/type when parsing model's returned text/numbers; don't directly stuff unfiltered model output into rendering contexts (red line 7; PDF in M9, but prefill text into frontend goes through Vue's default escaping).
