# M19 · 采购票据 AI 识别与 VAT 类型预填

> 🌐 [English](M19.md) · **中文**

> ⬜ **2026-11-10 已确认设计，待开发。** 本里程碑基于 `main` 上已验收的 M18。[路线图](../roadmap_zh.md)记录实施进度。当前已发布版本为 v0.14.0。

## 目标与范围

在现有 AI 票据识别中加入采购 VAT treatment 判断，减少人工选错类型的情况。收据收件箱审核表单自动预填，Expense 附件识别流程提供同样的建议。作者核对可编辑表单后，显式确认或保存。

目标字段是现有 `ExpenseInput.vat_treatment_id`。费用分类、VAT 税率和可抵扣性各有独立含义。首版识别 D1 中的三种现有采购类型。非 EU 采购、特殊情形及证据不足的情况由人工选择。

覆盖 M14 收据收件箱和 M8 Expense 编辑页。通过 M15 MCP 提交的票据共用收件箱识别和网页审核。外部销售识别、VAT 字典及报表映射、抵扣政策、周期性费用生成和历史入账记录均在本功能实施范围之外。此功能不包含自动入账、批量重新分类或新增 MCP 工具／权限。

## 冻结的产品与架构决策

### D1 · 根据票面证据分类

| 现有类型 | 提示词要求的证据 | 预期字典 effect |
| --- | --- | --- |
| `NL_DOMESTIC_PURCH` | 单据明确收取荷兰 VAT，并支持荷兰采购判断，例如荷兰商户的本地收据。 | `APPLY_RATE` |
| `EU_B2B_REVERSE_PURCH` | 证据识别出其他 EU 成员国供应商及荷兰企业买方，并明确写明向买方反向征税，或可确认是运抵荷兰的欧盟内供应。供应商未收取 VAT。 | `ZERO_REVERSE` |
| `EU_B2C_PURCH` | 单据明确收取另一个 EU 成员国的当地 VAT，证据与应用现有的外国 VAT 采购处理一致。 | `APPLY_RATE` |

这些代码限定识别功能的范围，运行时解析到当前公司的现有字典记录。名称、ID、税率及申报映射仍由数据驱动。界面使用现有 `EU_B2C_PURCH` 名称，建议本身不确定买方的法律身份。

综合实际开票实体、买卖双方角色、收取哪个国家的 VAT、税务措辞及交付信息。币种、单据语言、品牌总部、税率数字或单独的 `0%` 都不足以确定类型。荷兰境内反向征税、非 EU 采购、明显特殊税制、证据冲突、混合税务处理或同组混入无关交易时，类型建议留空，其他可识别字段仍可返回。EU 交易即使供应商未收 VAT，也可能需要自核税额，外国 VAT 则有单独的抵扣规则。[荷兰税务局 EU 采购说明](https://www.belastingdienst.nl/wps/wcm/connect/bldcontentnl/belastingdienst/zakelijk/btw/zakendoen_met_het_buitenland/goederen_en_diensten_afnemen_uit_andere_eu_landen/btw_berekenen_over_goederen_en_diensten/)、[跨境进项税说明](https://www.belastingdienst.nl/wps/wcm/connect/bldcontentnl/belastingdienst/zakelijk/btw/btw_aftrekken/welke_btw_is_aftrekbaar/btw_aftrekken_als_u_zakendoet_met_het_buitenland)。

### D2 · 扩展现有提示词并校验一条建议

每次识别通过共享采购核心调用模型一次。保留现有提取指令、自定义补充 `receipt_prompt`、日期上下文及 EN/ZH 解释性文本语言行为。在自定义指令和运行时上下文之后、最终 JSON 输出契约之前，追加固定采购分类指令。输出契约保持为最后一段。

分类段描述 D1，为三类各提供一个正例，并提供只有零 VAT、国家信息冲突、境内反向征税和非 EU 单据的反例。要求将单据内容视为不可信证据，忽略印在单据中的指令。自定义提示词不能扩展可接受类型代码或输出 schema。即使提示词要求合规输出，后端也必须校验。

模型可以返回包含 `code` 和 `reason` 的 `vat_treatment_suggestion`。理由是一条简短的纯文本票面依据，例如「德国供应商向荷兰企业开票，注明 reverse charge」。理由跟随所请求的 EN/ZH 语言，最长 240 字符。提示词要求省略完整 VAT 号码、地址及其他无必要的识别信息。代码与语言无关。

服务要求该值为对象，代码为受支持的字符串，理由为去除首尾空白后的非空字符串。超长理由、结构错误和明显矛盾的组合均拒绝，包括 `EU_B2B_REVERSE_PURCH` 同时带有解析后的正数供应商 VAT 金额。无效时仅丢弃类型建议，保留其他有效提取字段。证据不足时返回空建议。现有整体 `confidence` 仍作参考，不增加按置信度自动选择的门槛。

通过现有按公司隔离的 VAT 服务解析代码。匹配记录必须属于当前公司、处于启用状态、`side=PURCHASE`，且 effect 符合 D1。记录缺失、停用或语义改变时不给建议。受信任的 UUID 始终由服务解析，不取自模型。复用已有授权和公司隔离，避免散落新的公司过滤条件或新增分类表。

只把校验后的建议保存到收件箱现有 JSONB。理由使用转义后的文本插值展示。公共建议和日志继续排除提供商原始回复、凭据、编码原件及存储路径。

### D3 · 保护人工选择并应用当前建议

| 当前类型字段 | 收到新有效建议后的行为 |
| --- | --- |
| 空白且未操作 | 自动填入，并标记来源为 AI。 |
| 由上一条 AI 建议填入 | 更新为新建议。 |
| 人工选择或人工清空 | 保留当前值，若有不同的可用建议，则显示「采用建议」操作。 |
| 从已保存 Expense 加载 | 保留当前值，建议不同时提供「采用建议」。 |
| 已显式点击「采用建议」 | 后续识别将其视为人工选择。 |

在字段旁显示字典名称、AI 来源和证据。人工值与建议相同时无需重复显示采用操作。最新完成的识别失败或没有可用类型时，移除旧建议，并且只清除该建议拥有的类型值，保留人工值。文件组变化时使旧建议失效。同组重试期间可以暂时保留原 AI 类型值，但必须显示运行中状态，且旧采用操作不可用。

应用前，将建议的 ID 和代码与页面已加载的采购字典核对，包括启用状态和预期 effect。字典晚于识别结果到达时，加载后重新尝试应用，仍保护人工编辑。建议不可用时保留手选能力。人工保护以本次表单会话为界，与现有未保存收件箱表单一致。

只有当前条目、当前文件组和最新识别的结果才能更新建议状态。处理切页、详情／修改请求响应重叠、确认和保存，使迟到结果不能应用到其他条目或恢复过期建议。继续使用收件箱服务的文件修订号和提取代次检查。Expense 保存后，当前类型成为已保存的人工值。

Expense 编辑页只允许向已有 Expense 上传附件，因此该入口通常对已保存类型提供显式采用操作。采用建议只修改可编辑表单，作者保存后才持久化。收件箱确认继续通过现有原子确认流程创建一笔 Expense。

### D4 · 分开处理票面 VAT 与反向征税申报名义税率

现有 Expense 记录保存票面净额／VAT 金额以及 VAT 税率。对于 EU B2B 反向征税，报表服务使用该税率计算自核 VAT。供应商零 VAT 无法确定申报名义税率为零。荷兰税务局要求先确定所购商品或服务适用的荷兰税率。[荷兰税务局 EU 采购税额计算说明](https://www.belastingdienst.nl/wps/wcm/connect/bldcontentnl/belastingdienst/zakelijk/btw/zakendoen_met_het_buitenland/goederen_en_diensten_afnemen_uit_andere_eu_landen/btw_berekenen_over_goederen_en_diensten/)。

对于经过校验的 EU B2B 反向征税分类，保留提取的票面 `vat_amount`，该次识别不返回可预填的 `vat_rate_percent`。提示词要求人工核对名义税率，服务强制执行此分离。票面 VAT 金额缺失时继续为空。即使已识别的反向征税代码无法解析到合格字典项，也抑制该次税率预填。

两张采购表单选择反向征税类型时，禁止 AI 把票面税率应用到名义税率字段。AI 类型变更导致需要人工选名义税率时，清掉被替代 AI 建议之前填入的税率。已有人工或已保存税率保留供复核。显示本地化提示，要求核对或选择适用的名义税率。其他识别类型继续使用现有税率字典和提取行为。

选中反向征税类型期间，普通「净额乘税率」预览不得覆盖票面 VAT。类型或相关输入变化时使待执行定时器和响应失效，避免较早的普通 VAT 请求覆盖票面金额。票面金额保持可编辑，已失效的含税总额预览清空，等待有效的现有后端结果。金额计算仍全部在后端服务中。M19 不增加新的报表计算，也不根据类型建议推断可抵扣性。

## 契约与数据兼容

| 接口面 | 增量变化 |
| --- | --- |
| 模型 JSON | 可选 `vat_treatment_suggestion` 对象，包含 `code` 和 `reason`，也可为空。 |
| `ExpenseAIPrefill` | 新增可选、可空且默认为空的 `suggested_vat_treatment`，包含 `id`（UUID）、`code`（字符串）及 `reason`（去除首尾空白后 1–240 字符）。 |
| `POST /api/v1/expenses/ai-extract` | 返回扩展后的预填响应，沿用现有请求和错误处理。 |
| `ReceiptInboxRead.ai_suggestion` | 共用扩展后的预填类型和现有 JSONB 存储。仅含有效类型的建议也算可展示，可进入 `READY`。 |
| 前端生成 API 类型 | Step 1 增加响应契约时，重新生成已提交的 `schema.d.ts`。 |

模型字段携带候选代码，公共响应字段携带服务解析后的字典引用。模型提供的 ID 等未知字段不能成为受信任的引用。Schema 验证结构，服务执行分类检查和字典解析。

旧建议没有新增字段时按空值读取。无需数据库迁移、历史回填或自动重新提取。现有 `ExpenseInput` 确认／保存请求仍是入账契约。AI 失败沿用现有不可用／失败状态及人工审核回退。只有有效类型的结果为 `READY`，其他缺失字段仍需要复核。M15 传输／状态契约和 M16 外部销售识别保留各自范围。

## 部署自测与验收

使用 M19 构建和隔离测试数据，通过默认 dev Compose 启动 `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d`。在设置中配置已有 AI 提供商。里程碑报告提供具体样例及清理步骤。

1. 向收件箱上传荷兰本地 VAT 票据。检查自动填入本地类型及简短依据。核对其他字段，确认生成一笔带原件的 Expense。
2. 上传明确的 EU B2B 反向征税发票。检查建议类型、供应商收取的 VAT 和人工名义税率提示。选择适用名义税率，编辑净额，确认预览仍保留票面 VAT。确认 Expense，并对照保存金额与现有 VAT 报表预览。
3. 上传明确收取另一个 EU 国家 VAT 的票据。检查 `EU_B2C_PURCH` 及依据，确认并核验既有报表行为。
4. 分别上传一份非 EU 单据和一份模糊单据。类型应需要人工选择，其他有效提取字段仍可使用。
5. 手动修改或清空建议类型，然后重试识别。验证人工保护，并显式采用另一条可用建议。再次重试，确认显式选择保留。对于未被人工操作的 AI 字段，验证新建议更新，以及最新结果不可用时清空。
6. 追加／删除文件、重试，并在识别过程中切换收件箱条目。验证建议和采用操作对应当前条目及当前文件。难以手工稳定复现的时序采用自动化竞态证据。
7. 打开已有 Expense，上传附件并启动识别。确认已保存类型保留，采用不同建议，核对全部字段后保存。重新打开验证持久化。
8. 打开存有旧版建议、缺少新增字段的收件箱条目。验证正常审核及手选类型。用隔离配置检查 AI 禁用／失败路径，确认仍可手工完成。
9. 通过既有 MCP 接收票据，打开网页审核链接，验证相同建议行为。只确认一次入账，检查 Expense／P&L／VAT 结果，并保留外部销售提取回归检查。
