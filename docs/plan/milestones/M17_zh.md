## 目标与范围

**目标**：为报价手动选择并排序 PDF 附录，预览、下载和邮件发送均输出一份“报价正文＋附录”的完整 PDF。

**包含**：
- 在现有内容库中增加仅公司内部可访问、可复用的 PDF 资料库。
- 仅当前报价可选用的专用 PDF 上传。
- 报价编辑页保存有序附录清单，支持原件预览／下载及明确的未保存处理。
- 页面级拼接保留文本／矢量内容、尺寸和方向，不整页栅格化；合并文件会重新序列化，不承诺与输入文件字节相同。
- 不可变原件、资料库下架／恢复、已接受报价只读，以及兼容字段省略的报价 API 扩展。
- 一致的预览／下载／邮件组合流程、限制、可操作的错误、租户隔离和双语界面。

**不包含／顺延**：
- 产品关联、自动推荐，或添加产品时自动勾选。
- 发票／估算／收款收据附录、转换时携带附录，或复制报价时复制附录。
- 宣传册作为独立邮件附件、单次发送覆盖清单、ZIP 导出或公开文件链接。
- 分隔页、封面、自动目录、统一连续页码、页面缩放或宣传册编辑。
- App 内精确的历史报价发送 PDF、报价修订链、替换正式留存产物，或修改 M12／M13 留存机制。
- 文件夹／标签／分类、自动匹配语言、完整资料版本管理、OCR／AI 提取、外部 URL 导入、批量上传、物理删除资料库文件或清理任务。
- 内容／报告生成，以及无关的地址／路线接入。

## 已冻结的产品与架构决策

### D1 · 附录清单属于报价

在现有报价编辑页末尾、保存操作前增加**附录**区域。用户从资料库选择、上传报价专用文件、预览／下载原件、拖动排序及移除选用。显示标题、来源、原文件名、页数和大小。不按产品或客户自动选择文件。

保存后的清单用于后续全部预览／下载／发送。选择、移除和排序变化纳入现有脏状态快照及未保存保护。移除只取消选用，不删除原件。同一清单中的重复文件 ID 无效。相同字节可以上传成不同文件记录，不自动按内容去重。

### D2 · 公司内部可复用资料库

在内容库增加 **PDF 资料**页签，不新增顶层导航。支持上传、标题搜索、分页、原件预览／下载、修改标题、下架及恢复。默认显示可用文件，可查看下架文件。“共享资料库”只表示当前已认证公司内复用，不是公开网络访问。

原始字节、原文件名、哈希、大小、页数及归属不可变。更新宣传册时上传新文件，再单独下架旧文件。不提供原位替换接口或资料库物理删除。改名或下架不改变已有报价的文件或选用标题快照；新选用条目保存时快照当时的标题。

已下架文件可以保留在同一报价已保存的清单中，也可以重排；不能新增到其他报价，在移除并保存后也不能重新加入，除非先恢复资料。依据数据库已保存成员判断，不信任客户端标记。恢复后可再次选择，不重写任何报价。

### D3 · 报价专用上传与保存语义

专用上传要求报价已经保存。新报价上传时提供**保存并继续**：校验／保存当前表单，留在已持久化 ID 的编辑页，再继续上传。保存失败或取消则不上传。普通保存按钮继续保留现有返回列表行为。

上传把文件保存为当前报价可用原件，并加入浏览器待保存清单；不改变已持久化清单。只有报价保存成功才提交选择和顺序。上传后放弃编辑，已上传文件仍保留在本报价文件选择器中，之后可以重新选择。无需匿名临时上传或过期机制。

专用原件保留到正常删除报价；取消选用不等于删除，v1 不提供独立文件删除或转入共享库命令。不能供其他报价选用。仅上传专用文件不增加已保存清单的版本。

### D4 · 生命周期、复制与转换

遵守现有报价编辑规则：**ACCEPTED 只读**，其他状态沿用现有规则。已接受报价可查看附录、下载原件，但不能上传、调整选择或排序。不新增已接受报价重新激活的状态转换。

**复制报价始终清空附录清单，不复制专用文件**，与来源状态无关。转换为发票时，原报价附录保留，发票不附加任何宣传册。这只是对现有复制／转换的范围有界增补，其余复制字段和财务语义不变。

### D5 · 统一的完整输出

保留现有 WeasyPrint 报价正文渲染，新增 `pypdf` 拼接页面。创建新 writer，先追加报价正文，再按已保存顺序追加全部选中文件。保留纸张尺寸、旋转和可打印内容；不栅格化、不缩放、不增加分隔页，也不在宣传册上叠加报价页眉页脚。参见 [pypdf 合并文档](https://pypdf.readthedocs.io/en/stable/user/merging-pdfs.html)和 [PdfWriter](https://pypdf.readthedocs.io/en/stable/modules/PdfWriter.html)。

预览和下载继续使用现有报价 PDF 接口，发送调用同一个组合服务。无附录时沿用现有渲染路径，不额外合并，也不增加附录专用输出限制。文件名和语言解析规则不变；只有报价正文切换语言，上传的宣传册不翻译、不自动换版本。

最终邮件只有**一个** PDF 附件。SMTP 前先完整生成，把同一次生成的附件交给 SMTP 及现有可选 Sent 副本流程；不为 Sent 独立渲染，也不把原宣传册另附一遍。不同预览／下载／发送请求不保证字节完全相同，因为现有渲染器可能包含变化的元数据。

### D6 · 输出失败明确，不静默遗漏

任一已选原件缺失／不可读、哈希校验失败、无法合并或超过限制，都中止本次完整输出，返回稳定错误，适用时附失败文件 ID，供界面映射可见标题。不退回仅报价正文，也不跳过出错附录。

组合失败发生在任何 SMTP 调用之前，不产生成功发送记录，不改变业务状态。真正发送失败和 Sent 副本失败沿用现有日志语义，包括无自动重试，以及仅 Sent 保存失败不改变 SMTP 成功。不记录 PDF 字节、提取内容、不安全的解析器错误或邮件凭证。

原件稳定不代表报价正文冻结，也不代表保留每次历史发送的精确报价 PDF。本里程碑的邮件追溯仍是现有日志及可选的供应商 Sent 副本。

### D7 · 两张 additive 表与事务内原件

附录原件使用 PostgreSQL `LargeBinary`／`BYTEA`，沿用项目现有数据库二进制留存模式，使文件与元数据事务保存，并由数据库管理删除，避免磁盘清理竞争。不扩展 `DocumentArtifact`，也不复用其发票／退款归属或输出指纹语义。数据库备份应包含新表，不需要新文件卷。

| 表／字段 | 定义 |
| --- | --- |
| `pdf_appendix_file` | UUID `id`、`company_id`、可空 `owner_quote_id`、`title` TEXT、不可变 `original_filename` TEXT、`pdf_bytes` BYTEA、`sha256`、`size_bytes`、`page_count`、`is_archived`、时间戳 |
| 归属 | `owner_quote_id IS NULL` 表示公司资料库，否则为报价专用原件；不能重新归属。专用文件不能下架，下架／恢复只用于资料库文件。 |
| `quote_appendix` | UUID `id`、`company_id`、`quote_id`、`file_id`、`sort_order`、`title_snapshot` TEXT；唯一 `(quote_id, file_id)` 和 `(quote_id, sort_order)` |
| Quote 扩展 | 非空整数 `appendix_version`，默认／回填 `0`；已有报价附录清单为空。 |

新表均使用现有 PostgreSQL RLS 和服务端派生归属。服务校验文件必须为本公司共享资料，或恰好属于当前报价的专用原件。猜测 UUID 不能关联其他公司或其他报价的专用文件。

**单公司边界（作者于 2026-11-04 澄清）：** v1 保持单公司／单用户。保留既有 Quote 访问方式与公司归属校验，新附录路径集中复用归属解析入口。M17 不为旧 Quote／Quote-line 表启用 RLS，也不引入多公司切换／RBAC。两张新表保留上述已定义的 RLS，报价专用文件归属约束仍须执行。这是有界功能新增，不是多租户改造。

使用数据库外键与 ORM cascade：删除报价时清除其 `quote_appendix` 和专用原件行，资料库文件保留。文件引用约束必须允许在同一事务删除，不依赖级联执行先后（使用延迟文件引用检查）。仍被引用的共享文件不得删除。不写手工删子项循环、文件删除钩子，也不按哈希把不同报价的专用文件记录共享。

JSON 不返回 `pdf_bytes`，元数据列表／读取查询不提前加载二进制大字段。UUID、哈希和大小／页数由服务端确定；客户端不能提交归属或可信校验结果。

### D8 · 并发与兼容

- `QuoteWrite` 增加有序 `appendix_file_ids` 及 `expected_appendix_version`；`QuoteRead` 增加 `appendices` 和 `appendix_version`。定价计算请求不增加文件字段。
- 创建时省略清单代表空；非空清单只能引用当前公司可用资料库文件。非空初始清单版本为 `1`，空清单为 `0`。
- 更新时省略字段保留清单／版本；显式空数组清空，显式 `null` 无效。传清单必须同时传预期版本，即便清单未变化。只有成员／顺序实际变化才递增；保留未变化成员的标题快照，新成员取新快照。
- 报价正文和清单同一事务保存，替换前校验归属、下架与限制。附录保存失败或版本过期不得部分保存正文。
- 写入、专用上传和接受操作锁定同一报价父行，取得锁后重新校验 ACCEPTED。资料归档／恢复资格检查持文件行锁；需要同时锁报价时，先报价、再按稳定 ID 顺序锁文件。
- 输出渲染前物化一致的报价／清单／原件快照；父行锁使相关报价更新、删除和接受与读取串行，不能靠多次无锁查询混合版本。SMTP 网络操作前释放快照锁。
- 旧调用方省略附录字段时行为不变；复制显式清空，旧发票／收据产物不变。附录版本不是新的全局报价修订机制，不改变财务计算。

### D9 · 文件校验、安全与限制

仅接收普通静态 PDF。有界 multipart 流式读取必须在通用上传落盘前拒绝超限数据；复用／提取 M13 有界上传技术，不改变其精确原件产物契约。先认证、解析目标，再处理文件；上传事务中重查生命周期。

校验声明 MIME、PDF 文件头、非空、可解析、全部页面可访问，以及安全复制页面并写出成功。拒绝加密 PDF（包括空密码加密）、数字签名及可填写／XFA 表单。不静默扁平化，也不承诺交互或签名保留。通过校验的原始字节原样保存。

组合时新建文档，不克隆来源 catalog。不导入脚本、自动／附加动作、启动动作或嵌入文件。清洗页面／注释动作：保留普通 `http`、`https`、`mailto` 链接；拒绝或剥离其他动作，包括文件和 JavaScript 链接，并保留静态页面内容。无法安全处理的来源在上传时拒绝。原件预览／下载仍需认证；不把上传 HTML 作为内容提供，不执行或抓取 PDF 中的外部资源。标题／文件名是不可信展示数据，需要转义及安全响应头。

| 后端类型化配置 | 默认值 |
| --- | --- |
| `max_appendix_file_bytes` | `10 * 1024 * 1024`（10 MiB） |
| `max_quote_appendices` | `10` 份 |
| `max_quote_appendix_input_bytes` | `15 * 1024 * 1024`（已选原件总大小） |
| `max_quote_pdf_bytes` | `15 * 1024 * 1024`（合并输出） |
| `max_quote_pdf_pages` | `200` 页（报价正文＋附录） |

单份原件超过页数上限在上传时拒绝；保存时检查份数、输入总大小和已选原件页数边界；合并后检查完整页数及输出字节。上传时重写的候选文件同样有大小边界。通过类型化 API 读取限制，Vue 不重复维护数值规则，也不耦合收据／历史产物限制。说明邮件编码会增加附件体积，供应商可能有更低邮件限制。

同步 PDF 解析／拼接在有并发边界的工作线程运行，不阻塞异步事件循环；reader／writer 按请求独立，各路径关闭资源。不新增后台队列，不改动现有 PDFium AI／收据管线或夹带解析器／线程重构。

## 契约（先定义）

以下路径均在 `/api/v1` 下，使用现有 MFA owner 权限及 RLS。列表沿用 `limit`／`offset` 和总数约定。先定义 Pydantic／OpenAPI，再实现；每个改契约的步骤重新生成 `schema.d.ts`。

| 方法／路由 | 输入 → 输出／行为 |
| --- | --- |
| `GET /pdf-library/limits` | `200 PdfAppendixLimitsRead`，返回 D9 五项已配置数值限制 |
| `GET /pdf-library` | 可选标题 `search`、`include_archived=false`、分页 → `200 PdfAppendixFileListResponse`；默认仅可用文件 |
| `POST /pdf-library` | 有界 multipart：必填 `file`、可选非空 `title`（默认原文件名）→ `201 PdfAppendixFileRead` |
| `PATCH /pdf-library/{file_id}` | `PdfLibraryFileUpdate`：可选非空 `title`、可选 `is_archived`，不接受字节或归属 → `200 PdfAppendixFileRead` |
| `GET /pdf-files/{file_id}/content` | 可选 `disposition=inline\|attachment`，默认 `attachment` → 已认证 `application/pdf` 字节与安全原文件名 |
| `GET /quotes/{quote_id}/appendix-files` | 分页返回本报价专用原件，包括未选文件 → `200 PdfAppendixFileListResponse` |
| `POST /quotes/{quote_id}/appendix-files` | 同上有界上传字段 → `201 PdfAppendixFileRead`，不改变已保存清单 |
| 现有 `POST /quotes`、`PUT /quotes/{id}` | 增加 D8 清单／版本字段，返回扩展后的 `QuoteRead` |
| 现有 `GET /quotes/{id}` | 增加有序 `QuoteAppendixRead[]` 和 `appendix_version`；不向集合列表摘要加入文件大字段 |
| 现有报价 PDF／发送路由 | 请求形式和成功响应类型不变，改用完整组合输出并声明组合错误 |

`PdfAppendixFileRead` 返回 ID、派生的 `source=LIBRARY|QUOTE`、适用时的所属报价 ID、标题、原文件名、SHA-256、字节大小、页数、下架状态和时间戳。`QuoteAppendixRead` 返回关联 ID、文件 ID、已保存顺序／标题快照及文件元数据。JSON 不含二进制。对报价专用文件调用资料库 PATCH 返回 `404`。

稳定错误：缺失／跨公司／其他报价专用文件引用返回 `404`；已接受报价写入（`QUOTE_APPENDICES_READ_ONLY`）、清单过期（`QUOTE_APPENDIX_VERSION_CONFLICT`）、新增选用下架文件（`PDF_LIBRARY_FILE_ARCHIVED`）返回 `409`；文件／输入／输出字节超限返回 `413`；PDF 无效／不支持、重复 ID、份数／页数超限或非法请求返回 `422`。已存文件／合并失败返回安全的 `500 QUOTE_PDF_COMPOSITION_FAILED`，已知时才带 `file_id`。错误使用稳定 `detail.code`，不暴露原始异常或路径。文件或组合失败不算 SMTP 尝试。

## 数据模型／迁移

- Step 1 新增两表、RLS／权限、索引和 FK／唯一／检查约束；Step 3 新增并回填 `Quote.appendix_version`。原件字节和元数据原子插入。
- 字节数／页数为正，保存顺序非负连续；约束文件／顺序唯一、同报价专用归属及 D7 级联行为。可空 owner 仅区分资料库／专用文件，不是堆叠多个无关业务 FK。
- 实现时从实际 `main` 迁移头部新增 additive 迁移。不改写已发布迁移，不在暂停的 M15 分支预留编号，也不引入 revision 冲突。
- 升级不创建文件／清单，不改旧 PDF／邮件记录，不触发重渲染或回填。正常数据库备份包含新原件；不增加文件系统垃圾回收或自动数据迁移。

## 原子步骤清单

## 🟢 部署自测点（里程碑验收）

以 `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d` 启动正常开发栈；使用测试 PDF 和作者选择的收件人。

1. 打开内容库 → PDF 资料，上传两份静态 PDF，含横版／非 A4 和中文文件名。检查标题搜索、限制、页数、预览、下载原件 SHA-256；改标题、下架、恢复；其他内容页签仍可用。
2. 新建报价，选一份资料库文件，再调用专用上传。保存并继续后应只有一份已保存报价、表单内容不变、仍在编辑页，然后上传第三份 PDF。混合来源刻意调换顺序，保存并重载。
3. 预览／下载完整报价，核对正文在前、附录顺序／内容／尺寸／方向正确，无多余分隔页，宣传册页脚未覆盖。切换报价语言，宣传册不变；另查一份无附录报价。
4. 修改已选资料库标题并下架，重载原报价，其标题快照／文件仍在且输出正常，新选择不能加入该下架文件。上传替代文件，确认旧报价仍用原字节。
5. 另上传一份专用文件，但不保存清单，检查离开／取消／保存提示。重开报价，已保存清单不变，新上传文件仍可重新选用。移除已选文件并保存，完整输出不再包含它，但原件未删除。
6. 向作者测试收件人发送，可选抄送和 Sent 副本。核对收件箱及已启用的供应商 Sent 中只有一个完整 PDF 附件。不能安全在真实供应商演练的失败分支依靠自动化，并单独记录。
7. 复制含两类来源的报价，附录为空且无专用文件复制，其余复制字段不变。接受原报价，上传／编辑／排序被阻止，查看／输出仍可用。在符合条件的测试流程中转发票，发票无宣传册，来源报价保留附录。
8. 尝试无效／加密／表单 PDF 和配置限制边界，报错明确且无部分保存。两个编辑会话保存冲突清单，第二次不能静默覆盖第一次。
9. 删除一份允许删除的临时报价，包含专用文件及共享资料选择；其专用文件／关联消失，资料库文件及其他报价清单保留。第二公司隔离和级联竞争若未人工演练，由隔离的运行时角色测试覆盖。
