## Dependencies and Existing Behaviour

- **M14 inbox**: `create_item` persists 1–5 validated PNG/JPEG/WebP/PDF originals, then `extract_item` stores advisory AI suggestions. The owner alone confirms a pending item into one Expense in the web app. M15 reuses this workflow and does not create a parallel receipt or Expense engine.
- **M3/M4/M6 master data**: customer search/create, products/materials, VAT records and document templates already exist. The agent may query them; it must ask the user when customer matching, prices or tax choices are ambiguous. It must not invent authoritative prices or VAT values.
- **M5/M6/M12 documents**: existing `QuoteWrite` and `InvoiceWrite` require a customer, date, tax mode and at least one line. Quote creation allocates a quote number and starts as `DRAFT`. Standard Invoice creation starts as an unnumbered `DRAFT`; the legal invoice number is allocated only on issue. Both use backend pricing services. The agent does not create a partially populated business record when required inputs are missing.
- **Deployment**: the app and PostgreSQL run in the existing Compose stack. The app port is bound to host localhost by default; Hermes and JAI initially run on the same server. `BASE_URL`, not the internal MCP address, supplies browser review links.

## Goal and Scope

**Goal**: let an authorized agent, initially Hermes through Telegram, submit purchase documents for later web review, resolve or create customers, and prepare editable draft quotes and Standard Invoices through a small, reusable MCP surface.

Included:

- A Streamable HTTP MCP endpoint in the existing JAI app, with revocable, scoped, long-lived application tokens managed by the owner in the web UI.
- Receipt submission and status lookup with original bytes, delivery idempotency, safe status/error reporting and a web review link. The first path is remote MCP with Base64 file arguments; Step 5 has a mandatory local streaming-adapter fallback if real Hermes image or PDF transfer fails.
- Customer search/detail/create; read-only product/material, document-template and VAT option lookup; calculation preview plus create/read/update for `DRAFT` quotes and Standard Invoices. The agent may update any company's existing draft after identifying it unambiguously.
- Telegram sender/chat restrictions configured in Hermes, per-token authorization in JAI, operation tracing, EN/ZH settings/help copy and an end-to-end author walkthrough.

Excluded:

- Agent confirmation or discard of inbox items; automatic Expense posting; automatic quote/invoice send, issue, status transition, conversion, payment or VAT filing.
- Agent writes to products, templates, VAT dictionaries or existing customer records. Advance, Final, Credit Note, refund and correction drafts are not exposed in M15; their dedicated existing services remain the future extension point, with no placeholder endpoint now.
- A JAI Telegram bot, webhook, Telegram credential or independent Telegram identity verification; public-Internet/OAuth deployment in v1; generic database or unrestricted CRUD tools.

## Frozen Product and Architecture Decisions

- [x] **D1 · Separate conversation and business roles**: Hermes handles natural language, Telegram attachment access, user/chat authorization, clarification and replies. JAI validates structured tool arguments, permissions and tenant ownership, and invokes existing services. JAI's AI receipt provider remains the M14 extraction path.
- [x] **D2 · Two trust checks**: configure numeric Telegram sender IDs and permitted chat IDs in Hermes, without allow-all grants for the accounting workflow. JAI authenticates the application token. Telegram source fields supplied by Hermes are trace and deduplication metadata, not identity proof; JAI must never claim to authenticate Telegram users independently.
- [x] **D3 · Scoped application tokens**: the MFA-authenticated owner creates a named token, selects allowed capabilities, sees the secret once and can revoke it immediately. Tokens do not expire by default. JAI stores only a digest and metadata, never the secret. The token identifies one company and creator; the runtime role uses that company context for RLS lookup, then verifies the secret before authorizing a tool. No owner cookie or password is given to the agent.
- [x] **D4 · Minimal tool surface**: expose only the tools in the contract below. Tool discovery may omit tools outside a token's scopes, but every call checks permission again. A browser API permission does not imply the same action is permitted through MCP. MCP quote updates are `DRAFT`-only even though the existing web quote lifecycle allows other editable states.
- [x] **D5 · Stable write IDs**: every mutation requires a caller-supplied `request_id`. A Telegram receipt uses a stable key derived from platform, chat and message ID (media-group ID for an album); separate operations from one message add an operation suffix. Other MCP clients supply their own stable UUID. Under the same company/token/request ID, identical operation and canonical arguments return the prior result; changed arguments return a conflict. A revoked token cannot recover a prior result.
- [x] **D6 · Atomic idempotency**: reserve the operation key, perform the business mutation and store its target/result in the same database transaction. Refactor only the affected service commit boundaries into transaction-friendly primitives while preserving existing web API behaviour. A crash or competing request must not leave a committed business object without a recoverable operation record. AI extraction happens after the durable receipt transaction, as in M14.
- [x] **D7 · Original-file transfer**: remote `submit_receipt` accepts Base64 content for 1–5 M14-supported files, enforces the M14 per-file limit and a total decoded limit of `MAX_FILES × max_receipt_bytes` before persisting, and bounds the encoded HTTP body before parsing. It never logs bytes. In Step 5, real Hermes must successfully send both an image and a PDF. If either fails because Hermes cannot supply tool-visible original bytes or the MCP payload is unreliable, deliver a small Hermes-side stdio MCP adapter in that same step. Its tool takes a local attachment path, reads only an approved attachment-cache root, and streams multipart to a token-protected JAI upload route that calls the identical intake/idempotency service. This fallback does not weaken the acceptance test or create another receipt model.
- [x] **D8 · Draft-only accounting boundary**: receipt suggestions stay pending until web confirmation. Quote and Standard Invoice tools call existing calculation and validation services; all money math stays in `services/`. Create returns `DRAFT`; update checks the current state under a lock. MCP exposes no send/issue/status/confirm tool. Document creation requires complete existing write-schema inputs; missing facts trigger Hermes clarification rather than a new incomplete-record schema.
- [x] **D9 · Safe source and audit data**: retain token ID, operation, request ID, source platform/chat/message IDs, target type/ID, outcome and safe error code. Do not copy original receipt bytes/Base64 from intake arguments, the raw M14 AI-provider response, bearer credentials from authentication, or raw request bodies into audit rows or logs. **Author-approved replay exception (2026-09-30, choices A + A1)**: `agent_operation` also stores a validated, tool-specific response snapshot so an identical authorized request returns its original full result even if the target was changed or deleted. This snapshot may duplicate customer contact/address/`extra` fields and quote/invoice lines, notes and amounts from the request; it remains after target deletion. It is company-RLS-protected, has no general listing API and is returned only through authenticated, same-token replay. Typed business-response free text is retained for exact replay even when a user supplied AI-like text; the system cannot infer arbitrary text's provenance. Reject recognizable bearer/JAI token formats and file data URIs or encoded file signatures in snapshots, but do not claim that content screening can classify every arbitrary user-supplied string. The intake and AI services must never pass their original file bytes, Base64 arguments or raw provider payload to the snapshot. Links use configured `BASE_URL`; unconfigured localhost links are a deployment failure in a phone-based walkthrough.
- **Receipt response timing under D9**: `submit_receipt` snapshots the durable submission result (`ai_state=NOT_RUN`, no AI error) in the same transaction as the inbox item. M14 AI extraction starts only after that commit. Its later state is read with `get_receipt_status`; Hermes should query status before replying with the extraction result. A replay returns the original `NOT_RUN` submission snapshot and never reruns intake or AI.

## Contract and Data Changes

### Owner API and data

- Add `agent_token`: UUID ID, `company_id` FK/RLS, owner creator FK, name, token digest/selector, a typed set of scopes, creation/last-used/revocation timestamps. The secret is returned only by creation. `GET /api/v1/agent-tokens` lists metadata; `POST /api/v1/agent-tokens` creates one; `DELETE /api/v1/agent-tokens/{id}` revokes it. All require the current MFA owner session. The settings panel provides create/copy-once/list/revoke UI in EN/ZH.
- Add `agent_operation`: UUID ID, `company_id` FK/RLS, token FK, unique `(company_id, token_id, request_id)`, operation name, canonical-argument digest, source metadata, target type/ID, validated tool-response snapshot, safe outcome/error and timestamps. It is the durable idempotency and trace record. A previously created target that was later deleted remains a recorded result; an authorized identical retry returns the original response snapshot and must not create a replacement. The snapshot's deliberate retention of response fields is the narrow D9 exception above, not permission to persist raw arguments or files.
- Define typed scopes for `receipt:intake`, `customer:read`, `customer:create`, `catalog:read`, `quote:read`, `quote:write_draft`, `invoice:read` and `invoice:write_draft`. Read/write tools require their corresponding scopes; quote/invoice calculation preview uses the matching read scope. Token creation must reject an empty or unknown scope set.
- The one-time token format contains a non-secret company selector and token selector plus at least 256 bits of random secret. The selector establishes transaction-local RLS context for lookup; only digest verification grants access. Runtime-role grants and raw-SQL RLS tests accompany the migration.

### MCP and upload interface

Mount a single Streamable HTTP endpoint at `/api/v1/mcp` before the SPA fallback, with the official Python MCP SDK and the parent app's lifespan. It has no separate container. Check the `Authorization: Bearer` header on every HTTP request; do not accept browser cookies as MCP authentication. Configure Host/Origin protection for the localhost-first deployment. Treat the fixed token scheme as a private-network integration, not a claim of full OAuth interoperability.

All mutating tools accept `request_id` and return `operation_id`, `status`, target ID and a safe web link where applicable. `status` distinguishes newly created from replayed results. Errors have stable codes for unauthenticated, insufficient scope, validation, ambiguous/missing target, non-draft state and duplicate request with changed arguments; no error echoes secrets or file bytes. M14 AI extraction failure is a successful pending receipt result with a safe `ai_error_code`, not a failed submission.

| Tool | Input and result | Required guard |
| --- | --- | --- |
| `submit_receipt` | `request_id`, `source`, `language=en|zh`, `files[{filename,mime_type,data_base64}]` → inbox ID, `ai_state`, safe `ai_error_code`, review URL | `receipt:intake`; M14 validation; 1–5 originals; durable item before AI. |
| `get_receipt_status` | inbox ID → pending/confirmed status, AI state/error and review URL | `receipt:intake`; same company; no confirmation or file content. |
| `search_customers` / `get_customer` / `create_customer` | Search/detail; `CustomerWrite` for create → customer ID/detail | Read/create scopes; no fuzzy auto-merge or customer update. |
| `search_catalog` / `list_document_templates` / `list_vat_options` | Bounded company-owned options needed to build document lines | `catalog:read`; no price/tax invention or writes. |
| `preview_quote` / `create_quote_draft` / `get_quote` / `update_quote_draft` | Existing quote calculation/`QuoteWrite` and UUID → server totals, status and web URL | Quote read/write scopes; update only locked `DRAFT`; no status change. |
| `preview_invoice` / `create_invoice_draft` / `get_invoice` / `update_invoice_draft` | Existing invoice calculation/`InvoiceWrite` and UUID → server totals, status and web URL | Invoice read/write scopes; Standard kind only; update only locked `DRAFT`; no issue/send. |


The exact MCP tool names are `submit_receipt`, `get_receipt_status`, `search_customers`, `get_customer`, `create_customer`, `search_catalog`, `list_document_templates`, `list_vat_options`, `preview_quote`, `create_quote_draft`, `get_quote`, `update_quote_draft`, `preview_invoice`, `create_invoice_draft`, `get_invoice` and `update_invoice_draft`. Tool inputs and outputs are typed Pydantic contracts; the MCP server exposes no extra generic or administrative tool.

Stable machine error codes are `MCP_UNAUTHENTICATED` (missing, invalid or revoked Bearer token), `MCP_INSUFFICIENT_SCOPE` (token lacks the required capability), `MCP_VALIDATION_FAILED` (invalid structured arguments or unsupported file), `MCP_TARGET_NOT_FOUND`, `MCP_TARGET_AMBIGUOUS`, `MCP_DRAFT_REQUIRED` (target is not an editable draft) and `MCP_REQUEST_ID_CONFLICT` (same request key with different operation or canonical arguments). The transport boundary uses `MCP_HOST_REJECTED` (Host outside localhost/loopback) and `MCP_ORIGIN_REJECTED` (Origin outside localhost/loopback). Responses never include token material or file bytes. Before Step 2, all MCP protocol requests, including initialize/discovery and tool calls, return `401 MCP_UNAUTHENTICATED`; unsafe Host and Origin are rejected first.

**Step 5 remote-transfer fallback gate**: use the local stdio adapter and protected streaming upload route in Step 5 if either a real Hermes image or PDF cannot be delivered through the remote MCP tool with its original bytes intact and a reliable tool result. Mock success does not pass this gate. Do not install the adapter pre-emptively; Step 5 must exercise both real file types and choose the fallback if either fails.

The optional fallback adds `POST /api/v1/agent/receipt-inbox`: token-authenticated multipart files plus the same `request_id`, source and language, returning the same submission result. The Hermes-side adapter exposes a local MCP tool that accepts the original cache path and forwards the file stream; it is installed only if Step 5's remote transfer gate fails. Do not accept arbitrary remote file URLs or make JAI fetch user-provided URLs.

## 🟢 Deployment Self-Test Points

Use the default dev Compose startup from `AGENTS.md`, then connect Hermes to JAI on the same host. The milestone report must give the author concrete commands/configuration and these walkthrough steps.

1. Create a receipt-only application token in JAI, configure Hermes' numeric Telegram sender/chat allowlists and MCP connection, then send an image and a PDF. Verify each original byte-for-byte in the M14 inbox, inspect the AI status and open each review link from Telegram on a phone. Retry/replay one message and verify no duplicate item.
2. Disable or misconfigure receipt AI, submit another file, and verify Hermes reports a pending item with a recoverable AI state. Correct the fields and confirm only in the JAI web app; verify exactly one Expense and the expected report effect.
3. Ask Hermes for a quote for an existing customer using catalog/template options; supply missing price/tax details when prompted. Verify a numbered `DRAFT` quote with backend-calculated totals, edit it in the web app, and confirm Hermes cannot mark it sent.
4. Ask for a quote for a new customer; inspect the matching candidates, create the customer when no match exists, then create the draft. Replay the same creation request and verify neither the customer nor quote duplicates.
5. Ask for a Standard Invoice draft, inspect its unnumbered `DRAFT` state and backend totals, then update it through Hermes and in the web app. Verify no issue/send or VAT report effect occurred and that non-Standard document requests are refused.
6. Revoke the token and verify new MCP calls fail. Test an unauthorized Telegram sender/chat and an insufficient-scope token; neither can create a confirmed Expense, sent document or any unauthorized draft.
