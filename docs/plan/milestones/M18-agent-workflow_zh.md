# M18 · 客户端通用 Agent 里程工作流

> 🌐 [English](M18-agent-workflow.md) · **中文**

本指南说明任何连接到 JAI 认证 Streamable HTTP MCP 端点的客户端都可采用的通用工作流。它补充 [M18 设计与验收记录](M18_zh.md)，不要求使用 Hermes、Telegram 或特定路线查询服务。

## 权限与效果

所有者创建带显式 `mileage:create` 权限的令牌。该权限只授予 `get_mileage_options`、`preview_mileage_expense` 和 `create_mileage_expense`。选项和预览是读取操作；成功创建会记入一条正式里程行程及其关联 Expense。请求确认前须说明这一会计效果。存量令牌不会自动获得该权限。每次调用（包括重放）都会检查令牌有效性和授权。

这是对较早 Agent 一概禁止 Expense 入账规则的狭窄例外：只有专用里程工作流可创建正式里程 Expense，且必须在用户确认完整 JAI 预览后执行。收据确认／入账，以及直接或通用 Expense 创建／编辑仍不可由 Agent 执行。所有者网页工作流不变。

## 收集完整行程

询问明确的行程日期和正数单程距离。澄清是否单程或往返；不可依赖客户端或 schema 默认值。收集已知的起点、终点、用途和备注。这些文本字段在 JAI 中可选，但提供后必须展示。

调用 `get_mileage_options` 并展示启用的交通工具类型。将用户说法匹配到一个无歧义的启用类型。名称有歧义时询问，不得猜测。用户未指定交通工具时，JAI 会解析公司默认值，预览须展示解析结果。不得根据名称推断 ID 或使用已停用类型。

一次创建调用只记录一条使用一种交通工具的行程。如果去程和返程距离不同或事实需分别记录，应将其作为两条单程行程分别收集和预览。每一程都必须作为独立、经用户确认的操作，使用各自的发起事件、请求 ID、预览和确认。不得将多程打包成一条里程记录。

## 路线依据与距离确认

如果客户端有可用的搜索或地图工具，可以查询路线建议。向用户展示起止地点、交通方式、建议单程公里数和来源。路线建议仅供讨论，不是记账输入：请用户确认或修正公里数。只将用户确认的单程距离发送给 JAI。不得向 JAI 增加路线供应商、坐标或路线查询。

如果搜索返回多条可能路线或端点不明确，应说明歧义并请用户选择／修正路线或提供距离。若搜索不可用、报错或无法给出可靠路线，应说明目前没有可靠建议并询问公里数。不得编造距离，也不得把受控测试夹具说成真实供应商查询。用户无法提供距离时，应在预览／创建前停止。

## 预览、确认与创建

预览前为本次记账尝试生成一个稳定 UUID。预览和创建使用相同的 `request_id`、可选 `source` 和完整 `mileage` 对象。包含所有已知的 `MileageExpenseWrite` 字段，不得发送额外字段。JAI 校验输入并返回规范化里程输入、解析出的交通工具和 Expense 分类、计算结果及 `preview_token`。

向用户展示所有已提供的行程字段、解析出的交通工具和分类、单程／往返选择、总公里数、生效费率和日期、金额、币种，以及路线依据和用户修正。财务数值仅取自 JAI。说明确认后会创建一条关联该行程的正式里程 Expense。等待用户对这份确切预览作出明确确认。任何字段修改都需要重新预览。

获得确认后，使用该次尝试原有的请求 ID、source、mileage 正文和预览凭据调用 `create_mileage_expense`。未获明确确认不得创建。按实际响应中的 `operation` 信封和 `mileage` 结果报告：新建还是重放、行程 ID、关联 Expense ID、金额／币种，以及原样返回的准确 `operation.web_url`。不得重建或规范化 URL。

## 重试与过期预览

- 创建后超时或响应丢失时，使用相同请求 ID、source、mileage 正文和预览凭据原样重试。成功重放会返回原结果；开始另一条行程前必须先这样处理。
- 同一 ID 搭配不同参数会冲突。绝不可在该 ID 下修改字段、来源或凭据。
- 若预览／创建报告预览过期、设置改变或尝试失败，应说明需要刷新之处。使用新的发起事件和新 UUID 开始新尝试，取得并展示新预览，再获得用户明确确认后创建。修正或重新确认的尝试不得复用旧 ID。
- Telegram 中仅使用安装的 helper，以可信发起事件和操作名 `create_mileage_expense` 派生元数据；完整原样传递其 `request_id` 与 `source`。第二程或重新尝试需要不同的可信发起事件。不得复制、猜测或修改 Telegram 来源 ID 来强行生成新请求 ID。
- 其他客户端在预览前生成 UUID，并在跨对话轮次的尝试状态中保留。若客户端使用 source 元数据，应保持不变。另一条行程或新尝试使用新 UUID；完全相同的网络重试保留原 UUID 和完整载荷。

凭据已撤销时不能创建或重放。缺少权限应作为所有者需处理的访问配置问题报告；不得尝试其他令牌、路由或工具绕过。

## 边界

校验、当前设置、费率、Decimal 计算、VAT 投影、已保存的行程／Expense 数值及重放结果均以 JAI 为准。客户端不计算或调整金额。Agent 不得使用这些工具确认收件箱收据、创建通用 Expense、修改里程、管理设置或执行其他 Expense 生命周期操作。既有零 VAT 里程投影和报表行为保持不变。

部署与集成作者验收请遵循 [M18 里程碑走查](M18_zh.md#部署自测与验收)。路线建议的自动化协议夹具须报告为受控场景；真实搜索／地图查询需单独记录客户端走查结果。
