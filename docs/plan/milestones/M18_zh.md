## 目标与范围

让获授权的 Agent 收集完整行程，取得 JAI 计算预览，请用户确认，再原子创建里程行程及关联 Expense。支持任何兼容现有 JAI MCP 连接与认证边界的客户端。

- 纳入启用交通工具选项、完整里程预览、确认后创建单条行程、稳定重试、owner 管理的权限和客户端通用工作流文档。
- Agent 可以使用自身可用的网页搜索或地图工具提供路线距离建议。用户确认实际用于记账的公里数。
- 历史里程列表／详情工具、里程修改删除、设置管理、草稿／审核队列、批量创建及 JAI 内置地图集成留待后续。既有费用读取继续遵循 SI4 范围。
- 基础包括 [M11 里程](M11_zh.md)、[M15 Agent 接入与幂等](M15_zh.md)和 [SI4 费用读取](../improvements/SI4_zh.md)。应用内共用地址搜索／路线查询仍由路线图 §4.ab 的独立待办承接。

## 已冻结的产品与架构决策

### D1 · 客户端通用的职责划分

Agent 理解自然语言、澄清缺失或有歧义的事实、在可行时取得路线建议，并请求确认。JAI 校验结构化输入、权限与公司归属，再通过现有里程服务解析费率、执行 Decimal 计算并生成 Expense 投影。所有展示的财务金额均来自 JAI。

搜索或地图结果须说明起止地点、交通方式、建议距离和来源。缺少可靠路线依据时，Agent 询问公里数。用户可以覆盖建议值。路线依据展示在对话中，用户要求保留的上下文可写入现有备注字段。本里程碑不为 JAI 增加地图供应商凭据、坐标、供应商响应存储或外部 HTTP 请求。

### D2 · 完整行程与明确确认

复用 `MileageExpenseWrite` 语义。要求明确的行程日期及正数单程公里数。省略交通工具 ID 时采用公司默认值，并在预览中展示。即使现有 schema 的 `round_trip` 默认 false，也必须明确展示单程／往返。起点、终点、用途和备注保持为可选文本。

选择用户指名的交通工具前读取启用类型，名称有歧义时追问。一条行程使用一种启用类型及现有私人交通工具商业里程流程。去返距离不同的行程拆成分别预览和确认的单程记录。每个操作创建一条行程。

Agent 展示所有已提供的行程字段、解析出的交通工具和分类、总公里数、生效费率／日期、金额和币种，等待用户确认。创建后生成正式里程 Expense，进入既有报表。MCP 描述与 owner 权限文案须明确这一效果。

### D3 · 预览绑定拟入账内容

JAI 返回带版本的 HMAC `preview_token`，使用既有签名密钥设施和规范化类型序列化。绑定公司、Agent 令牌 ID、请求 ID、可选来源、完整规范化行程输入，以及行程与 Expense 快照实际使用的解析结果。这些结果包括交通工具身份／名称、规则身份／适用类型／生效日／费率、总距离、金额、币种、分类和 VAT 投影事实。

采用 M18 专用签名用途标识／版本，以常量时间比较签名。默认按内容判断有效性，不另设时间过期。签名密钥轮换使尚未使用的预览失效。凭据表明 JAI 提供了哪份计算结果，Agent 负责取得用户确认。

预览执行完整创建校验，包括分类和 VAT 前提。创建时重新取得既有公司里程锁，解析当前事实，在插入业务数据之前核对凭据。实际保存必须使用刚核验的同一份解析结果。输入或相关解析结果变化后，需要重新预览和确认。无关配置编辑不会使内容相同的入账预览失效。

### D4 · 最新设置与原子事务

从既有里程创建服务提取仅 flush 的事务内基础操作。Owner API 包装层继续负责 commit／rollback。MCP 在 `run_agent_mutation` 内调用基础操作，将行程、关联 Expense 和操作快照一起提交。

预览和创建均在依赖查询前取得既有公司里程 advisory lock。费率／类型／默认值写入沿用现有锁顺序。为类型化设置读取增加可选缓存绕过能力，用于选项、预览和创建所需的里程默认值。绕过模式读取数据库，既不读进程缓存，也不向其写入，并保留既有类型校验和层级回退规则。

复用既有定价与投影逻辑。插入快照使用已校验的定价对象，避免签名核对到写入之间再次计算。创建者取已认证令牌的 owner。保持现有 Decimal 精度、币种舍入、零 VAT 投影和 P/L 行为。

### D5 · 稳定尝试与精确重放

预览前生成一个稳定 UUID，贯穿确认和创建，同一次尝试保留相同的可选来源元数据。在 Telegram 集成中，以发起该尝试的可信事件及 `create_mileage_expense` 操作名派生 ID。通用客户端可生成 UUID 并省略来源。

完全相同的网络重试使用原 ID、来源、正文和预览凭据。新行程、输入变更或失败／过期创建后的再次确认尝试使用新 ID。已提交成功但响应丢失时，必须先原样重试，再决定是否开始另一尝试。

复用既有公司／令牌／请求唯一约束及规范化参数摘要，摘要包含预览凭据。认证授权后，先检查已有操作，再按实时业务设置核验预览。成功重放返回原响应，即使设置已变或目标已修改／删除。已撤销凭据无法重放。沿用 M15 的失败操作持久化语义，因此修正后的尝试需要新请求 ID。

### D6 · 权限、隔离与结果留存

一个显式 `mileage:create` 权限授予三个录入工具，包含创建里程所需的有限选项／预览读取能力。存量令牌通过 owner 创建替代令牌取得该权限。每次调用都检查权限和撤销状态。

使用已认证的公司上下文和非超级用户 runtime role。Agent 令牌／操作表沿用其 RLS 策略。既有里程、设置和 Expense 访问按路线图 §3.3 及 M15／SI4 复用现有服务归属边界。MCP handler 不新增散落的公司筛选。测试须在 runtime role 下使用真实其他公司 ID，并准确描述隔离机制。

为 Agent operation 增加白名单内的里程响应快照及对应目标 ID 校验。快照按 M15 重放规则保留类型化行程字段、金额和原网页链接，包括目标删除后的留存。沿用既有凭据／文件内容筛查。预览凭据参与请求摘要，并排除于响应快照和日志之外。

## 契约

所有工具使用现有 `/api/v1/mcp` 端点。根参数及嵌套里程输入拒绝未知字段，同时复用既有里程字段类型与校验。距离支持现有 Decimal 表达。调用方提供原始行程输入，费率和财务数值由 JAI 提供。

| 工具 | 输入 | 输出 | 权限 |
| --- | --- | --- | --- |
| `get_mileage_options` | 空类型化对象 | `default_transport_type_id`、仅含启用类型的 `transport_types[{id,name}]` | `mileage:create` |
| `preview_mileage_expense` | `request_id`、可选 `source`、包含完整 `MileageExpenseWrite` 字段的 `mileage` | `request_id`、规范化 `mileage`、解析出的 `transport_type{id,name}`、`expense_category{id,name}`、采用 `MileageCalculationRead` 的 `calculation`、`preview_token` | `mileage:create` |
| `create_mileage_expense` | 相同的 `request_id`、`source`、`mileage`，另加 `preview_token` | 既有 `AgentWriteResult` 信封，加采用 `MileageExpenseRead` 的 `mileage` | `mileage:create` |

规范化预览输入将空值／省略的交通工具选择保留为 null，`transport_type` 则给出解析后的默认类型，以便检测预览到创建之间的默认值变更。来源使用既有 `AgentSource` 契约校验。UUID 和日期沿用既有 API 序列化。

创建返回 `operation_id`、`status=created|replayed`、等于行程 ID 的 `target_id`，以及基于 `BASE_URL` 生成的 `/expenses/mileage/{trip_id}/edit` 网页链接。里程响应包含关联 Expense ID。持久化重放载荷由类型化里程响应和网页链接组成，常规信封由 Agent operation 重建。目标类型使用 `mileage`。

选项和预览不创建行程、Expense 或 Agent operation 行，令牌最近使用时间仍正常记录。当前已交付工具面为 18 工具／九权限。Step 2 后计划为 20 工具／十权限，Step 3 后为 21 工具／十权限。

### 错误行为

- 复用 `MCP_UNAUTHENTICATED`、`MCP_INSUFFICIENT_SCOPE`、`MCP_VALIDATION_FAILED`、`MCP_TARGET_NOT_FOUND` 和 `MCP_REQUEST_ID_CONFLICT`，以及现有 Host／Origin 边界错误。
- 显式交通工具 ID 不存在或属于其他公司时，均返回 `MCP_TARGET_NOT_FOUND`。类型停用，或默认值、费率、分类、VAT 配置缺失／无效时，返回 `MCP_MILEAGE_CONFIGURATION_INVALID`。
- 缺少预览凭据或凭据结构非法时，按输入校验失败处理。结构合法但与当前尝试／解析结果不匹配的凭据返回 `MCP_MILEAGE_PREVIEW_STALE`，Agent 应重新预览并请求确认。
- 操作包装层先处理已有请求 ID 冲突，再执行实时预览校验。解析新尝试时遇到的配置／查找错误保留上述错误码。
- 新错误须加入 MCP 安全错误白名单及类型化错误词汇表。不得返回原始校验输入、凭据或数据库异常。

## 数据模型与迁移

- 复用里程行程、Expense 和 Agent operation 表。扩展类型化操作快照白名单，支持 `mileage` 及其行程 ID。
- 在当前 `0057` head 之后新增 Alembic 迁移，将 `mileage:create` 加入令牌 scope CHECK 约束。保留已发布迁移及存量令牌／操作行。
- 沿用 SI4 降级保护。任何存量令牌包含 `mileage:create`，包括已撤销令牌，都使收窄约束的降级事务失败。该保护阻止回退时，运维恢复配套的升级前备份。
- 将类型化 scope 加入 owner 令牌 API 及 EN／ZH Agent access UI。契约改变时重新生成并提交 OpenAPI TypeScript 类型。新权限文案明确其允许创建正式里程费用。

## 原子任务卡

依赖顺序为 **1 → 2 → 3 → 4**。每张卡遵循路线图 §5 DoD，相关测试覆盖 Happy Flow 和 Corner Cases。使用隔离临时资源并清理。实施简报保持本地且被忽略。

### Step 1 · 里程创建支持外层事务

- **目标／契约**　交付事务内基础操作，保持现有 owner 请求／响应行为。
- **后端**　提取仅 flush 的创建逻辑，owner 包装层保留 commit／rollback，复用同一定价、快照和 Expense 投影。增加可选设置缓存绕过，并贯穿里程默认值解析，供后续录入使用。
- **前端／迁移**　此内部服务步骤无需增加。
- **测试**　既有 owner 创建／读取／计算及报表回归。外层回滚同时移除行程和 Expense，异常无半条记录，基础操作不提交。预热过期进程缓存后验证最新默认值、类型校验和层级回退，并验证绕过模式不缓存未提交值。
- **盲审点**　金额计算路径唯一，事务归属清楚，提交前响应可用，owner API 行为兼容，缓存改动范围受控。
- **DoD／简报**　仓库门禁及 `review-notes/M18-step1-impl.md`，包含自动化证据和 owner API 走查。

### Step 2 · 权限、选项与可信预览

- **目标／契约**　按上述 schema 和错误定义交付 `mileage:create`、`get_mileage_options` 和 `preview_mileage_expense`。
- **后端／迁移**　实现 additive scope 迁移、逐次授权、类型化工具、完整创建前提、规范化签名及使用最新默认值的公司锁内预览。本步仅暴露已可工作的工具。
- **前端**　增加本地化权限名称／说明，重新生成 TS 类型。文案说明创建工具交付后，此能力允许创建正式 Expense。
- **测试**　默认／指定类型、停用／缺失／其他公司类型、空／无效选项、单程／往返、Decimal 边界及溢出、无适用费率、分类／VAT 配置无效、额外字段拒绝、授权／撤销，以及业务和操作行零插入。验证规范化等价值、所有签名输入／解析字段、跨令牌／公司签名、迁移兼容及降级保护。覆盖权限 UI 和生成类型。
- **盲审点**　预览完整且可确认，使用真实创建前提，跨进程设置保持最新，权限映射准确，错误安全，旧令牌兼容。
- **DoD／简报**　两个工具可通过 MCP 调用，门禁通过，`review-notes/M18-step2-impl.md` 包含协议证据及权限／预览走查。

### Step 3 · 确认创建与精确重放

- **目标／契约**　交付 `create_mileage_expense`、里程结果快照及稳定失败／重放行为。
- **后端**　接入 `run_agent_mutation`、owner 归属、锁内预览校验和 Step 1 创建。持久化已核验的定价对象。扩展目标类型、快照白名单、ID 匹配和安全错误。基于 `BASE_URL` 生成现有里程编辑页链接。
- **前端／迁移**　使用现有里程编辑页和列表。实现若暴露额外 OpenAPI 契约变化，重新生成类型。
- **测试**　创建／投影成功、篡改预览、输入／默认值／费率／分类变化、跨公司／令牌尝试、权限不足、相同请求并发、载荷冲突、提交后响应丢失、各写入边界回滚及撤销竞争。设置变化、目标编辑／删除、签名密钥轮换后，重放仍返回存储的成功结果。失败／过期尝试须用新 ID。继续覆盖既有 owner 创建、费用读取、P/L 和零 VAT 行为。
- **盲审点**　新写入必须有匹配预览，已核验事实与持久化事实一致，操作与业务行原子提交，重放不创建替代目标，结果筛查和租户校验有效。
- **DoD／简报**　三工具组成完整流程，门禁通过，`review-notes/M18-step3-impl.md` 记录正常和重试走查。

### Step 4 · 通用工作流与里程碑验收

- **目标／契约**　文档化完整工作流，并用隔离数据完成跨 MCP 边界验证。
- **文档**　在 `docs/plan/milestones/M18-agent-workflow.md` 及其镜像新增客户端通用双语指南，涵盖类型选择、路线依据／手填回退、完整预览、明确确认、跨轮稳定 ID／来源、响应丢失重试、过期后新尝试和准确结果链接。从 README 和当前完整 Hermes 工作流链接至该指南。更新该工作流的工具白名单和里程专用说明，包括其已有的一概禁止 Expense 入账的规则。保留其他角色专用配置的权限范围及 M15 历史验收证据。
- **协议验收**　使用专用 PostgreSQL 数据库、临时 loopback TCP MCP 服务和两家合成公司，在 runtime role 下验证发现、选项、预览、创建、重放、权限不足、撤销和其他公司 ID。受控路线依据覆盖有效建议、歧义和查询失败回退。所选客户端部署走查具备实际网页／地图能力时，执行真实查询。
- **门禁**　Ruff、strict Mypy、默认及完整隔离 PostgreSQL 集成测试、前端测试／构建、codegen 无漂移、Docker build 和双语一致性。核验既有里程 owner 流程、费用读取及财务报表。
- **盲审点**　实现符合 D1–D6，文档适用于不同客户端，公布的工具数与交付一致，证据区分协议自动化与真实客户端／人工检查，本地简报未跟踪。
- **DoD／报告**　写 `review-notes/M18-step4-impl.md` 和 `review-notes/M18-report.md`，包含命令、预期结果、实际证据、跳过项及下方完整走查。作者完成走查或明确委托等价验收后再记录验收。

## 部署自测与验收

按默认 dev Compose 执行 `docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d`。使用隔离测试数据及 owner 创建的测试令牌。里程碑报告提供具体 MCP 客户端配置和清理步骤。

1. 在 Agent access 创建带 `mileage:create` 的令牌。核对本地化能力说明、可用交通工具和默认值，检查旧令牌缺少权限。
2. 提供日期、单程距离、往返选择和可选行程文本。检查完整预览并确认，再检查原样返回的网页链接、行程和关联 Expense。
3. 选择另一种启用交通工具，核对其适用费率。在预览前走一次缺失或有歧义的用户描述。
4. 让 Agent 展示路线建议和来源，修正公里数，再预览／确认修正后的行程。查询无法提供可靠距离时走手填回退，记录实际使用真实查询还是受控证据。
5. 预览后修改默认交通工具、适用费率或分类。检查受影响的旧预览被拒绝，再以新尝试 ID 重新预览、确认和创建。
6. 模拟响应丢失后原样重试创建。确认只有一条行程、一笔 Expense，并返回原重放结果。同 ID 改载荷应冲突。
7. 核对里程列表、关联 Expense 及报表中的后端金额和既有零 VAT 处理。确认 owner 网页里程创建仍正常。
