## 目标与范围

**目标**：通过三个范围有界的增补，改善单据编辑、报价复用与邮件追溯体验。

**包含**：
- Invoice、Quote、Estimate 编辑页的明细行拖动排序。
- 将已有 Quote 复制为独立的新草稿。
- 开启后，将所有新发邮件连同附件保存到供应商服务器的 Sent 文件夹。

**不包含 / 顺延**：
- Estimate group 排序、拖动改变分组、编辑器按组重构。
- 新舍入算法、独立排序 API、分离显示顺序与计算顺序。
- Quote 版本链、版本比较、自动替换旧报价。
- Sent 副本重试队列、自动重试、手动仅补存副本、历史邮件回填。
- 产品手册 PDF 上传／存储及发送报价时勾选额外附件。登记为后续单独设计的 Milestone 候选；现在不预留 schema 或 Milestone 编号。

**相关文档 / 已有基础**：[路线图](../roadmap_zh.md)、[M5](../milestones/M5_zh.md) 定价与 Invoice CRUD、[M6](../milestones/M6_zh.md) Quote CRUD 与编号、[M6.5](../milestones/M6.5_zh.md) Estimate 分组、[M7.5](../milestones/M7.5_zh.md) 舍入、[M9](../milestones/M9_zh.md) PDF／邮件，以及 [M12](../milestones/M12_zh.md)／[M13](../milestones/M13_zh.md) 正式单据留存。

## 冻结的产品与架构决策

- [x] **D1 · 复用普通保存与计算**：拖动调整前端明细数组，普通保存通过已有 `sort_order` 持久化。排序后刷新预览，保留最后一个适用行承担整单折扣舍入尾差的现有规则。作者接受小额舍入差异，以控制本次范围；这不构成新的数值上限保证。
- [x] **D2 · 保留现有编辑边界**：仅在当前编辑器允许改明细时启用拖动。已发邮件附件和已留存正式 PDF 字节不回写；可编辑单据的新渲染结果按新保存顺序输出。
- [x] **D3 · Estimate 排序仅供内部使用**：保留分组归属、group 顺序与 group→Quote 汇总规则。不新增 Estimate PDF 接口；生成 Quote 的组顺序维持现状，之后可在 Quote 编辑页调整公开明细。
- [x] **D4 · 副本是一份新 Quote**：分配新编号，设为 `DRAFT`，报价日期为当天，有效期按公司当前默认天数生成。复制内容与原始价格输入，通过现有服务按当前 VAT 配置计算。
- [x] **D5 · 不复制业务历史**：不复制付款、结算模式／锁、转换关联、单据链历史、邮件日志或留存 PDF。源与副本独立，不增加版本管理模型。
- [x] **D6 · Sent 保存默认关闭，开启后覆盖全部新邮件**：包括报价、所有支持的发票类型、收款收据、退款确认、测试邮件及密码重置。IMAP 复用实际生效的 SMTP 用户名／密码，不增加另一套凭据。
- [x] **D7 · SMTP 与 IMAP 结果独立**：SMTP 接受邮件后才尝试保存。IMAP 失败不能将发送标为失败、回滚业务／PDF 留存结果或触发再次 SMTP 发送。不包含自动重试或事后仅补存副本。
- [x] **D8 · 复制完整邮件**：SMTP 与 IMAP 使用同一份序列化 MIME，包含正文、To、CC 及全部附件，两阶段 Date、Message-ID 保持一致。字节仅在当前请求期间持有，不增加持久原始邮件存储。
- [x] **D9 · 解析已有服务器文件夹**：有明确配置则使用指定文件夹；否则发现唯一可选的 `\Sent`，没有匹配时尝试已有且可选的 `Sent`。匹配多个或无可用文件夹时要求明确配置，不任意选取、不自动创建。
- [x] **D10 · IMAP 安全且有界**：支持 SSL/TLS（默认 993）和 STARTTLS（通常 143），验证证书，不提供明文模式。切换安全方式不静默覆盖显式填写的端口。网络等待有界，连接可靠关闭。若供应商已自动保存 SMTP 邮件，应关闭开关避免双份；SI1 不承诺跨供应商自动去重。

## 契约（先定义）

### 单据排序

- 复用已有创建／更新／计算接口与明细数组，数组顺序继续作为持久化和输出的顺序依据。
- 不增加排序接口或 schema 字段。稳定的客户端行标识仅属于 UI，不进入业务请求。

### Quote 复制

- `POST /api/v1/quotes/{quote_id}/duplicate`，无请求体 → `201 QuoteRead`。
- 使用现有 MFA owner 认证、公司隔离和编号机制。源不存在／不可访问 → `404`；普通无效引用／配置沿用 Quote 校验错误。
- 保留客户、参考编号、币种、税务模式、VAT treatment／税率选择、折扣输入、备注／内容文本及有序原始明细输入。不重新读取目录价格覆盖复制的单价。
- 所有源 Quote 状态均可复制，包括已接受或已转换的报价。新记录始终使用新标识、`DRAFT`、未设置的结算模式、空的转换／历史关联及新计算的金额。
- 列表复制已保存内容；已有编辑页存在未保存修改时，复用现有“保存后继续／取消”保护。尚未保存的新 Quote 不显示 Duplicate。成功后跳转副本编辑页。

### SMTP 设置与 Sent 副本结果

为 `GET/PUT /api/v1/settings/smtp` 增加带类型的嵌套 `sent_copy` 配置：

| 字段 | 默认值 / 含义 |
| --- | --- |
| `enabled` | `false` |
| `host` | 空；启用时必填 |
| `port` | `993`；合法 TCP 端口 |
| `security` | `SSL_TLS`；另支持 `STARTTLS` |
| `folder` | `null` 表示自动发现；空白输入归一化为 `null` |

- 旧 PUT 省略 `sent_copy` 时保留已存值；旧设置缺少该配置时按关闭读取。保留现有密码保留／更新／清空语义及脱敏方式。
- 从实际生效的 SMTP 配置解析 IMAP 凭据，包括现有环境变量回退；SMTP 回退到环境变量时仍保留已保存的 Sent 配置。缺少可用凭据时返回安全的配置失败，不增加第二套凭据表单。
- `EmailLogRead` 增加 `sent_copy_status: NOT_ATTEMPTED | SAVED | FAILED`、可空 `sent_copy_error_code` 和可空 `sent_copy_saved_at`。SMTP 失败或关闭保存 → `NOT_ATTEMPTED`；APPEND 成功 → `SAVED`；副本尝试失败／结果不确定 → `FAILED`。`status`／`sent_at` 始终只表示 SMTP 结果。
- `POST /api/v1/settings/smtp/test` 在 SMTP 成功后保留 `202`、`status="sent"`，通过带类型的响应增加相同副本结果字段。IMAP 失败返回警告结果，不视作 SMTP 测试失败；SMTP 失败沿用原错误响应，但错误详情必须安全。
- 密码重置保持原有对外语义，副本失败通过安全结构化运行日志记录，不向业务邮件日志模型加入密码重置记录。
- 契约变化后生成 TypeScript 类型。业务路由保持薄层，发送与保存逻辑放在 `services/`。

## 数据模型与迁移

- Sent 配置保存在现有 GLOBAL SMTP JSONB 设置中，不增加设置表或凭据列。
- `email_log` 增加 `sent_copy_status`（非空，默认 `NOT_ATTEMPTED`，约束为带类型的取值）、`sent_copy_error_code`（可空 text）、`sent_copy_saved_at`（可空带时区时间戳）。
- 历史行填 `NOT_ATTEMPTED`、详情为空；不推断历史副本成功，不改变原 SMTP 状态、留存 PDF 或单据数据。
- 一致更新 ORM、序列化和失败邮件日志重建辅助函数。保留现有公司归属、RLS 与外键行为；不新增业务表或原始邮件存储。
- 迁移接在 main 当前线性 head 上，验证新库、生产形状旧库升级及隔离环境降级／升级，不接入暂停中的 M15 迁移链。

## 原子实施步骤清单

### Step 1 · 单据明细拖动排序

- **状态**：已完成（2026-10-25），自动化门禁及独立盲审通过。
- **目标**：Invoice、Quote、Estimate 编辑页可调整明细，保存后刷新及后续输出保持顺序。
- **契约**：无 API 变化，使用有序数组，预期生成类型零漂移。
- **前端**：使用 Vue 3 `vuedraggable`，封装共享的拖动手柄排序容器，普通选字／输入不触发拖动。Invoice／Quote 增加稳定行标识，Estimate 复用已有标识；覆盖已加载单据、套用模板及新增行。保存／加载期间或当前规则禁止修改明细时禁用拖动。
- **预览**：每次计算请求同时捕获行标识，按标识关联返回金额，忽略已被取代的结果。排序触发普通后台预览，不在 Vue 计算金额。
- **后台／PDF**：复用数组→`sort_order`、ORM 读取排序与 PDF 渲染；仅修复回归测试证实的排序缺陷，保持定价及 Estimate 分组汇总规则不变。
- **迁移**：无。
- **测试**：新建／编辑、首尾移动、内容相同行、新增／删除后排序、输入状态保留、快速移动与过期预览、保存失败、刷新、只读状态；验证持久顺序和 Invoice／Quote HTML／PDF 顺序，包含排序后 Quote 转 Invoice。Estimate 分组归属／group 顺序及生成的公开分组保持不变。
- **金额回归**：整单固定折扣、混合 VAT 与尾差案例应等于现有引擎对相同新顺序输入的结果，不断言总额与顺序无关。已发附件／留存 PDF 字节不变。
- **盲审重点**：稳定标识覆盖所有行来源；不泄漏 UI key，不新增前端计算、独立排序接口、编辑权限或分组行为。
- **DoD**：路线图 §5；实现后写本地 `review-notes/SI1-step1-impl.md`。

### Step 3 · 完整发信保存到服务器 Sent

- **状态**：已完成（2026-10-25），自动化门禁及独立盲审通过。
- **目标**：开启后，每次成功发信都尝试供应商侧副本，并准确展示两个阶段的结果。
- **契约／迁移**：先定义上述设置／结果 schema、兼容规则及日志迁移，在前端集成前生成类型。
- **后台**：只构造一次邮件，加入 Date／Message-ID，按 SMTP 换行序列化，同一份字节交给 SMTP 与 IMAP。标准库 `imaplib` 放入工作线程，socket 等待有界；验证 TLS、使用实际 SMTP 凭据认证、正确解析／编码文件夹、以 `\Seen` 及适当内部日期 APPEND，再关闭连接。
- **失败流程**：分开发送异常与 IMAP 异常；SMTP 已接受时保持 `SENT`，即使保存失败也保留 PDF 及业务结果。连接清理失败不能覆盖已确认的 APPEND 成功。APPEND 结果不确定时记副本失败且不自动重试。只记录稳定安全错误码，不记录原始协议响应、凭据或 MIME 内容。
- **发送入口覆盖**：业务邮件、测试、密码重置统一接入共享路径；业务副本结果持久化，测试副本结果返回，密码重置失败安全记录。不为系统邮件伪造业务日志关联。
- **前端**：扩展现有 SMTP 表单，增加开关、IMAP 地址／端口／安全方式／文件夹及说明；测试分别展示 SMTP 和 Sent 结果。发送弹窗和日志面板区分发送失败与“已发送，但保存到 Sent 失败”；完成 EN/ZH、加载和错误状态。说明供应商已自动保存时应关闭开关。
- **测试**：默认关闭、旧设置／PUT 兼容、密码脱敏／保留、环境回退、SSL/TLS／STARTTLS、配置／认证／TLS／超时失败、明确指定／自动发现／缺失／多义文件夹、带空格及非 ASCII 文件夹名、两阶段正文／CC／附件／Message-ID 一致；所有网络调用均用替身，覆盖全部发送入口。
- **失败回归**：SMTP 失败不调用 APPEND；IMAP 失败不重发、不改变 SMTP 成功、不回滚已留存 PDF、不泄密；历史日志迁移保留；已确认 APPEND 成功不被清理失败覆盖。
- **盲审重点**：无入口绕过共享路径，IMAP 异常不进入 SMTP 失败分支；设置保留凭据与环境回退；不增加队列、历史回填、任意文件夹创建或原始邮件落盘。
- **DoD**：路线图 §5；写本地 `review-notes/SI1-step3-impl.md`。

## 🟢 部署自测点（issue 验收）

使用默认开发 Compose 启动：

```sh
docker compose -f docker-compose.yml -f docker-compose.dev.yml up -d
```

1. 分别新建／编辑三种单据，拖动、保存、刷新，确认顺序保留；Estimate 分组归属及 group 顺序不变。包含新增一行后移动到相关旧行旁边的场景。
2. 下载并发送排序后的 Invoice／Quote，检查 PDF 顺序；已发附件与正式留存 PDF 不变；只读单据不能拖动。
3. Duplicate Quote，确认新编号、当天日期、默认有效期、复制内容／顺序及独立状态；修改副本确认源不变，并验证未保存修改的保存／取消保护。
4. 配置 IMAP，发送测试邮件及带 CC／PDF 的业务邮件；在供应商 webmail Sent 中查看正文／收件人／CC，下载附件核对发送的单据；使用测试账号验证密码重置邮件保存。
5. 暂时错误配置 IMAP，保持 SMTP 有效，发到测试收件人；确认收到邮件、界面只报副本失败、业务邮件日志保持 `SENT`，且没有自动重发。恢复配置后新邮件正常保存，旧失败副本不回填。
6. 关闭 Sent 保存，确认普通发信正常。如果供应商已经自动保存 SMTP 邮件，则保持关闭，验证供应商原生行为，不再启用第二条保存路径。

最终报告需明确哪些邮件类型做了人工验证，哪些依赖自动化覆盖；未执行的供应商侧检查不能记为通过。

## 协议参考

- [RFC 9051 §6.3.12 — IMAP APPEND](https://www.rfc-editor.org/rfc/rfc9051.html#section-6.3.12)：将完整邮件保存到服务器邮箱。
- [RFC 6154 — 特殊用途邮箱](https://www.rfc-editor.org/rfc/rfc6154.html)：发现 `\Sent`；部分供应商本身就会自动把已发邮件放入其中。
- [Python 3.12 imaplib](https://docs.python.org/3.12/library/imaplib.html)：SSL/TLS、STARTTLS 与 APPEND 客户端接口。
